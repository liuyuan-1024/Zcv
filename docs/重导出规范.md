# 重导出规范

本文规定所有 crate 的公共门面与可见性边界。具体导出清单以各 crate 公共入口和 README 为准，不在本文复制。

## 基本原则

公共 API 由真实的跨 crate 消费关系决定，而不是由目录层级或未来可能复用决定。

1. 默认保持私有。
2. 只在父模块内部使用时，使用私有项或最窄的 `pub(super)`。
3. 需要在当前 crate 多个模块间共享时，使用 `pub(crate)`。
4. 存在明确的外部消费方时，才从 crate 公共入口 `pub use`。
5. 外部消费结束后，应删除重导出并收窄原定义可见性。

`pub` 不是消除编译错误的快捷方式。先确认消费方是否应该跨越边界；如果不应该，应移动代码或改变调用方向。

## 公共门面

每个 crate 的 Cargo `lib.path` 指向其公共入口。入口负责：

- 声明内部模块；
- 重导出稳定的跨 crate 协议与类型；
- 提供确有必要的初始化入口；
- 用简短模块文档说明 crate 职责。

消费方应依赖 crate 根门面：

```rust
use zcv_workspace::{Item, Workspace};
```

不要依赖实现子模块路径，也不要为了暴露某个深层类型把整棵模块树设为 `pub mod`。

## 可以公开的内容

- 跨 crate 使用的领域协议、数据类型和错误类型。
- 由多个外部消费方使用的稳定基础组件。
- 具体能力向框架注册所需的入口。
- 调用方完成合法工作流所必需的方法。

## 不应公开的内容

- 只有 crate 内部调用的辅助函数、布局结构和缓存。
- 仅供测试绕过公共行为的内部步骤。
- 单一消费方的组件或未来可能复用的抽象。
- 可从公共状态确定性派生的影子数据。
- 为保留旧路径而存在的转发模块、别名或双轨 API。

测试需要观察行为时，优先通过公共结果、事件或渲染状态验证。只有确实属于 crate 内部不变量的测试，才放在同 crate 内使用最窄可见性。

## 类型擦除与注册

类型擦除只用于框架确实需要容纳异构实现的边界，例如工作区 `ItemHandle`、`PanelHandle` 或 UI 输入工厂。具体实现仍应拥有自己的状态。

注册入口必须满足：

- 框架不依赖所有具体实现方；
- 注册发生在明确的应用初始化阶段；
- 接口只暴露框架真正需要的能力；
- 不借注册表建立任意跨模块访问。

如果只有一个调用方且不存在依赖倒置需要，不应引入注册表或类型擦除。

## 清理步骤

进行可见性清理时：

1. 搜索定义、重导出和所有调用方。
2. 判断外部消费是否符合模块职责。
3. 移动错误归属的代码，或将 API 收窄到最小范围。
4. 删除失效的重导出、兼容别名与未使用导入。
5. 运行受影响 crate 的编译检查和相关行为测试。

不要在项目级文档维护逐 crate 的符号目录；它会与源码重复并快速失效。
