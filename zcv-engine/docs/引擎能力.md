# 纯粹底层编辑引擎能力

> 目标：定义 `zcv-engine` 作为工业级、单机、纯文本编辑引擎底座应承担的长期能力边界。

`zcv-engine` 面向编辑器宿主提供可靠的文本编辑核心。它维护文本、坐标、事务、版本、历史、快照、通用区间追踪和底层验证等事实，不替宿主实现 Editor 显示投影、UI、协议业务、项目管理或用户操作语义。

本文只写稳定能力边界和架构方向，不记录实现阶段、细碎清单或完成流水账。当前状态和建议命令见 `docs/STATUS.md`。

## 判断标准

一项能力进入本 crate，必须至少满足以下判断：

- 它直接维护编辑引擎不变量。
- 它属于文本存储、文本编辑、坐标、事务、历史、快照、通用追踪、逻辑文本读取切片或底层验证。
- 它是宿主无关的通用底层事实，而不是某个产品层功能。

只是“宿主可能会用到”的能力，不默认进入 `zcv-engine`。

## 负责范围

- 文本存储与局部编辑。
- `ByteOffset` / `TextRange` 为核心的强类型坐标模型。
- 事务提交、变更映射、Delta 事件和原子失败。
- Undo / Redo、历史节点、事务记录与回放。
- 只读快照、版本绑定和本地读写边界。
- Selection / SelectionSet 数据原语、PositionMap 映射与纯文本边界查询。
- Anchor、Mark、TrackedRange、MetadataLayer、VersionedResult、VersionedRangeSet 等通用区间追踪原语。
- 逻辑文本 Viewport slicing；显示投影由宿主 Editor 负责。
- 单 Buffer 同步匹配、替换和版本化结果承载。
- 文件文本进入和离开 Buffer 时的编码、换行、保存点和 reload 边界。
- 大文件策略、历史预算、防御性错误处理、property / fuzz 等验证能力。

## 非目标

- UI 渲染、主题、字体测量、像素坐标、窗口系统。
- Editor 折叠、隐藏区间、显示坐标投影和占位符。
- LSP / Tree-sitter provider 或完整协议实现。
- diagnostics、semantic tokens、inlay hints、code lens 等业务结果生成。
- 项目索引、文件树、插件系统、跨文件搜索与替换。
- 快捷键、菜单、命令面板、Command / CommandExecutor。
- IME composition、marked text、候选框和窗口系统输入协议。
- 宏录制、用户操作回放、用户输入设备分类。
- 后台任务调度器、取消令牌、线程池、优先级调度。
- 实时多人协作、CRDT、OT、远程光标、presence 和网络同步协议。

## 核心架构原则

- `ByteOffset` 是唯一权威、持久的核心编辑坐标。
- `CharOffset`、`Utf16Offset`、`Line`、`LogicalColumn`、`DisplayColumn`、grapheme 边界都是派生坐标或视图坐标。
- Public API 不用裸 `usize` 表达领域坐标。
- `TextRange` 必须保持 `start <= end`。
- `Transaction` 必须绑定 `base_version`，提交时必须校验版本。
- 事务失败必须保持原子性，不部分修改文本、版本、dirty、history 或订阅状态。
- Buffer 只保存共享文本状态；当前 SelectionSet 和 SelectionHistory 属于宿主的具体 Editor view。
- engine 只接收已经形成的文本编辑；IME marked text 在提交前不进入 Buffer。
- `ChangeSet` / `Delta` / `PositionMap` 只能由已验证编辑构造。
- `Snapshot` 必须只读、低成本、绑定 `BufferVersion`，并可跨线程读取。
- 生产存储使用 `RopeyStorage`，不自研 Rope / Piece Table / Piece Tree。
- 测试 reference model 可以使用简单字符串模型，但不进入生产存储核心。
- 目录模块是实现分层；长期 public API 由 crate root 统一导出。

## 能力域

### 文本存储与文件边界

引擎负责把外部文本安全载入 Buffer，并以适合大文件和局部编辑的结构保存、读取和修改文本。文件路径、编码、BOM、换行风格、保存点、dirty 状态、reload 和只读策略属于底层边界；文件监听、冲突交互和保存 UI 不属于本 crate。

### 坐标与文本数学

核心编辑语义以 UTF-8 byte offset 表达。其他坐标只通过显式转换进入编辑模型。坐标系统需要保护 UTF-8、UTF-16、CRLF、tab 展开、display column、word / subword / symbol boundary 以及可恢复错误边界。

### 编辑事务与变更映射

所有文本变异应归一化为已排序、不重叠的 edit 列表，并通过事务提交。事务提交产生版本推进、Delta、ChangeSet、PositionMap、changed ranges 和可选历史记录。引擎不关心事务来源是键盘、鼠标、格式化器还是外部系统。

### 历史、快照与版本

Undo / Redo 是编辑引擎核心能力，负责恢复文本并返回被回放历史节点的规范 `TransactionId`。宿主以该身份从自己的 SelectionHistory 恢复视图选区；HistoryEntry 和 TransactionRecord 不保存某个 Editor 的 SelectionSet。历史节点、历史预算、事务记录、回放和版本化结果都应围绕已提交文本事务展开。Snapshot 是只读版本事实，用于后台读取、搜索、宿主显示投影和外部结果过期判断。

### 光标、选区与组合输入

Selection / SelectionSet、归一化、PositionMap 映射以及 word / subword / symbol 边界属于 engine 的宿主无关事实。多光标 edit 生成、移动、删除、indent / outdent 与编辑后的 SelectionSet 属于宿主 Editor；Buffer 只接收已形成的 Transaction，也不保存当前选区。IME composition、marked text、相对选区和候选框属于宿主输入协议；只有输入法提交后的文本才通过普通编辑事务进入 engine。

### 区间追踪与外部结果承载

任何需要跟随文本变化的位置或范围，都不应只是裸 offset。Anchor、Mark、TrackedRange、MetadataLayer、VersionedResult 和 VersionedRangeSet 负责表达版本绑定、范围跟随、失效策略、payload 承载和 UTF-16 边界转换。业务类别应保留为泛型 payload 或自定义 kind，不在引擎中膨胀成专用 adapter。

### 读取切片与宿主显示投影边界

引擎提供版本绑定的 `Snapshot`、逻辑文本 Viewport slicing、`Anchor` / `TrackedRange`，以及每个消费者独立累积的 `TextSubscription` / 可组合 `TextPatch`。宿主事件只负责唤醒；消费者读取当前 Snapshot，再消费自己的 Patch。Tab 展开、display-column、Fold、隐藏区间、Projection、ProjectedRange、投影 viewport 和占位符属于宿主 Editor 的 DisplayMap，并原生消费组合 Patch。这样同一 Buffer 可以被多个 Editor 视图以不同节奏、折叠与 Tab 配置展示。

### 单 Buffer 搜索与替换

当前 Buffer 内同步 literal / regex 匹配、结果版本绑定、range tracking、单次替换和 replace all 原子事务属于文本编辑底座。后台执行、任务调度、取消、进度、跨文件搜索和结果面板属于宿主。

### 防御、性能与验证

工业级底座必须对异常输入、巨大文本、超长行、超大事务、历史内存增长、版本冲突和边界坐标保持可诊断、可测试、可恢复。验证应覆盖机器契约、随机编辑、差分测试、性能基准和必要的可观测指标。
