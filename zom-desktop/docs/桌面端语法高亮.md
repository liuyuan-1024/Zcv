# 语法高亮设计手册

> **本手册在高亮系统中的位置**：zom 桌面端整体采**渲染层统一、生产层分散**的高亮架构（见 [`桌面端高亮架构.md`](桌面端高亮架构.md)）——选区、搜索匹配、diagnostics、AI 提案等各自是独立 producer，由 `HighlightComposer` 统一合成。**语法高亮是这一架构的第一个 producer**。本手册只规定该 producer 内部的产出机制；与其他高亮的叠加、优先级、上屏合成规则不在本手册，全部在高亮架构手册。
>
> **设计立场**：zom 不做语法高亮，只消费工业界已验证的高亮源——首选 [tree-sitter](https://tree-sitter.github.io/)，其次 LSP semantic tokens。本手册定义的全部内容都是「把这些外部系统装进 zom 所需的最小宿主壳」，不引入任何 zom 私有的词汇表、scope 规则、theme 约定或高亮算法。
>
> 由此推论：
>
> - 不自研高亮算法（包括 regex / TextMate scope 引擎）。
> - 不定义 token 词汇表；name 取值域 = tree-sitter highlight name 命名空间。
> - 不规定 theme 必须覆盖哪些 name；theme 生态对齐 tree-sitter 上游（Helix / Zed 兼容口径）。
> - 本手册主体是 trait、共享 tree、版本守护、调度——「最小宿主壳」本身。
>
> 编辑面在字符层怎么消费这些 span 是渲染端的事，不在本手册范围。

## 参考

- [`桌面端高亮架构.md`](桌面端高亮架构.md)：高亮系统全局架构。本手册的 syntax producer 落入该架构的「第一个 producer」位置；与其他高亮（选区 / 搜索 / diagnostics / ...）的合成规则、装饰协议、优先级档位都在那本手册。
- [`引擎能力.md`](../../zom-engine/docs/引擎能力.md)：本手册引用的 `BufferVersion` / `ChangeSet` / `Snapshot` 由 `zom-engine` 提供，类型定义与不变量见此。
- [tree-sitter highlight names](https://tree-sitter.github.io/tree-sitter/syntax-highlighting#highlights)：本手册采纳的 name 命名空间的上游规范。

## 一、定位与边界

- **是什么**：宿主侧的可插拔 producer 子系统。按 buffer 喂语言识别 → 选 provider（tree-sitter 或 LSP）→ provider 在后台维护一棵 tree-sitter 解析树，写入跨线程共享的 [`BufferSyntaxTreeSlot`]；paint 端按 viewport 现查 Query 出 spans。
- **不是什么**：
  - 不在 `zom-engine` 实现。Engine 提供 `Buffer` / `Snapshot` / `ChangeSet` 基础设施，不知道「语法高亮」这个业务类别。
  - 不绑定任何特定 parser 实现细节。Provider 形态是 trait，tree-sitter / LSP / 占位实现都通过同一 trait 接入；trait 只是这两类 provider 的最小公共面。
  - 不解析颜色 / 字重 / 字号。Provider 只产 name + 修饰位，theme 在 desktop 端解析为样式。
  - **不缓存 spans**。颜色 = 当前 tree 在 viewport 上的纯函数，每帧 paint 现查。
- **在分层中的位置**：

```text
┌─────────────────────────────────────────────────────┐
│ zom-desktop      theme 按 tree-sitter name 解析样式  │  阶段 3（字符层）
│                  paint 端按 viewport 现查 Query       │
├─────────────────────────────────────────────────────┤
│ 高亮调度层       SyntaxWorker 串行承载 provider 调用    │  本手册主体
│                  共享 BufferSyntaxTreeSlot 主线程 ↔ 后台 │
│ HighlightProvider 实现（tree-sitter / LSP）          │
│ Language Registry（识别 + 选 provider）               │
├─────────────────────────────────────────────────────┤
│ zom-workspace    BufferId / WorkspaceBuffer 句柄     │
│ zom-engine       Buffer / Snapshot / ChangeSet      │
└─────────────────────────────────────────────────────┘
```

调度层与 provider 实现当前统一寄存在 `zom-workspace::syntax`；后续若拆出独立 crate `zom-syntax`，不影响下游 API。

## 二、Token name

Token name 的取值域 = **tree-sitter highlight name** 命名空间（点分小写，如 `keyword.control.import` / `function.builtin` / `string.special.url`）。

- **本手册不维护词汇表，不裁剪子集，不规定别名**。具体取值由各语言的 `highlights.scm` 决定，是 tree-sitter 上游的事。
- LSP provider 内部把 `SemanticTokenType + modifiers` 映射到 tree-sitter name，用公开的标准映射表实现；映射表落在 LSP provider 模块内，不外溢。
- 渲染端按完整 name → 点分前缀 → 默认前景色逐级回退查询 theme。**回退链是本子系统的不变量**——任意 name 必有 fallback，绝不漏渲染。
- Theme 是否覆盖某个 name 不归本手册管：覆盖得多就细，覆盖得少就糙，都合法。

携带类型见 §三。

## 三、HighlightSpan

[`BufferSyntaxTree::query_viewport`] 的返回元素。

```rust
pub struct HighlightSpan {
    pub name: HighlightName,           // tree-sitter highlight name，&'static str newtype
    pub modifiers: TokenModifiers,     // bitset：static / readonly / deprecated / async / ...
}

pub struct HighlightName(&'static str);
```

- 不带颜色、不带字体；纯 name + 修饰位。
- 区间在 query 返回的 `(TextRange, HighlightSpan)` 元组里携带，不挂在 span 内。
- `modifiers` 用 bitset 平铺（主要服务 LSP token modifiers），theme 端按需叠加样式（如 `deprecated` → 下划线 + 半透明）。tree-sitter provider 默认产 0 修饰；少数语言在 highlight name 里编码了类似信息（如 `variable.builtin`），按 name 直接表达，不强行拆到 modifier。

## 四、HighlightProvider trait

tree-sitter 与 LSP 两类 provider 的最小公共面。trait 本身不假设语言学语义，只规定生命周期与产物存放方式。

```rust
pub trait HighlightProvider: Send + Sync {
    fn language(&self) -> LanguageId;

    /// 把一个 buffer 挂上来开始供应高亮——provider 在此调用内做首次 parse。
    fn attach(&mut self, buffer: BufferHandle);

    /// buffer 发生编辑后调度层通知 provider。
    /// tree-sitter provider 在此调用内做增量 reparse；
    /// LSP provider 只更新内部版本号，真正推送来自 server 异步回包（未来形态）。
    fn on_edit(&mut self, buffer: BufferHandle, change: &ChangeSet, version: BufferVersion);

    /// buffer 关闭 / 切换语言 / provider 卸载时调度层调用。
    /// Provider 必须释放与该 buffer 相关的全部资源；调用返回后不得再向 slot 写任何内容。
    fn detach(&mut self);

    /// 把 provider 当前持有的「语法树 + 对应 snapshot」导出到共享槽位。
    /// 调度层在每次 attach / on_edit 处理完成后调用。
    fn export_syntax_tree(&self, slot: &BufferSyntaxTreeSlot) { let _ = slot; }
}
```

**关键点**：

- **产物落 slot，不走 sink / 不走 layer**。调度层不再持「高亮投递队列」，渲染端不再读「高亮层」。worker 每条 Job 处理完调一次 `export_syntax_tree`，slot 里始终持有 worker 已知最新的 tree。
- **provider 不持有 `Buffer`**。它通过 `BufferHandle` 借调度层提供的只读 snapshot 接口，禁止直接持有 engine 内部句柄。
- **provider 内部状态归 provider**。tree-sitter 的 `Parser` / `Tree` / `last_snapshot`、LSP 的请求队列都封装在 provider 实现里，不外溢。

## 五、共享 tree slot 与版本守护

```rust
pub struct BufferSyntaxTree {
    config: Arc<SharedConfig>,    // language + query + capture lookup
    tree: tree_sitter::Tree,      // 当前已知的最新 tree
    snapshot: Snapshot,           // 与 tree 对应的 buffer snapshot
    version: BufferVersion,
}

#[derive(Clone)]
pub struct BufferSyntaxTreeSlot { /* Arc<Mutex<Option<Arc<BufferSyntaxTree>>>> */ }

impl BufferSyntaxTreeSlot {
    pub fn load(&self) -> Option<Arc<BufferSyntaxTree>>;
    pub(crate) fn store_if_newer(&self, tree: BufferSyntaxTree);
    pub(crate) fn try_edit(&self, edits: &[InputEdit], new_snapshot: Snapshot, new_version: BufferVersion) -> bool;
    pub(crate) fn clear(&self);
}
```

**版本守护规则（不可绕过）**：

- worker 写回（`store_if_newer`）必须比较版本：当前 slot 版本 ≤ 新 tree 版本才覆盖。worker 真跑了过期 reparse 时静默丢弃，避免把过期 tree 盖到主线程已 `tree.edit` 推进过的更新版本上。
- 主线程编辑入口（`BufferSyntax::handle_edit`）做两件事：
  1. **同步**克隆当前 slot 里的 tree、逐条 `Tree::edit(InputEdit)` 推进字节坐标，写回 slot。这一份是「interpolate tree」——字节坐标对齐新 snapshot 但**结构未变**。paint 端此时拿到的 tree 已能正确返回 viewport 内 shifted node 的 query 结果。
  2. **异步**投 `Job::Edit` 给 worker 去跑真正的增量 reparse；回包后通过 `store_if_newer` 把结构正确的 tree 覆盖 slot。
- `detach` 清空 slot；下一任 provider 不会读到旧 tree。

**为什么 Mutex 而不是 arc_swap**：tree-sitter 的 `Tree::clone` 是 `O(1)`（内部 `Arc` 共享），加上"两侧都要写"的现实（主线程 `tree.edit` + worker reparse），单写多读的 arc_swap 范式不直接适用。锁临界区只包**载 / 存 Arc**，最长一次 `Tree::clone` + `tree.edit(InputEdit)`，均 `O(log N)`；锁竞争窗口比"主线程 paint 内的整段 query"短两个量级，不构成拖帧来源。

## 六、Language Registry

```rust
pub struct LanguageId(&'static str); // "rust" / "typescript" / "markdown" / ...

pub struct LanguageRegistry { /* ... */ }

impl LanguageRegistry {
    pub fn register(
        &mut self,
        id: LanguageId,
        detectors: Vec<LanguageDetector>,
        provider_factory: Box<dyn Fn() -> Box<dyn HighlightProvider> + Send + Sync>,
    );

    /// 优先级：用户显式声明 > shebang > mode-line > 扩展名 > 默认 plain。
    pub fn detect(&self, path: Option<&Path>, first_line: Option<&str>) -> LanguageId;

    pub fn make_provider(&self, id: LanguageId) -> Option<Box<dyn HighlightProvider>>;
}

pub enum LanguageDetector {
    Extension(&'static [&'static str]),       // ["rs"]
    Shebang(&'static [&'static str]),         // ["python", "python3"]
    ModeLine(&'static [&'static str]),        // 当前识别路径未消费；保留枚举位
    Filename(&'static [&'static str]),        // ["Makefile", "Cargo.lock"]
}
```

- 一个 `LanguageId` 对应**一个**默认 provider 工厂。当前不做多 provider 叠加（tree-sitter + LSP 合成）；trait 不阻止，调度层暂不实现。
- 注册接口只接 `Box<dyn HighlightProvider>` 工厂闭包，**不在编译期把 provider 集合写死**。这是后续可换 dynamic loading 的关键 —— 静态注入与动态注入对 registry 而言无差别。

## 七、调度层

```text
            ┌─────────────── BufferSyntax（主线程句柄）─────────────┐
            │  per BufferId：language + tree_slot + worker handle    │
            └────────────────────────────────────────────────────────┘
                  ▲                       │                       ▲
   buffer.events  │                       │ Job::{Attach,Edit,    │ slot.load()
                  │                       ▼  Detach}（mpsc）        │（每帧 paint）
            zom-workspace          SyntaxWorker（后台单线程）
                                   provider.{attach,on_edit,detach}
                                          │
                                          ▼
                                   provider.export_syntax_tree(&slot)
                                          │
                                          ▼
                                   BufferSyntaxTreeSlot
```

调度层职责：

1. **生命周期**：监听 workspace 的 `open_file` / `close_buffer` / language change，做 `attach` / `detach` 配对。每个 buffer 最多 1 个活跃 provider，归属在 worker 线程上。
2. **编辑入口**：监听 buffer 的 `DeltaEvent`，主线程同步推进 slot 字节坐标，异步投 `Job::Edit` 给 worker 跑 reparse。
3. **Worker 串行**：所有 buffer 共享一根 `SyntaxWorker` std::thread，串行处理 Attach / Edit / Detach。每条 Job 用 `catch_unwind` 包住——某 buffer 的 provider 触发 panic 不会拖垮线程，只丢弃出问题的 entry，该 buffer 退化成 plain。
4. **降级**：provider 工厂缺失 / 文件超阈值 / detect 命中 `plain` → 不 attach，buffer 显示默认前景色。
5. **同步等待**：`SyntaxWorkerHandle::wait_for_idle` 仅供测试 / bench 使用，正常前台路径不该走。

## 八、Provider 形态

trait 同一，内部差异完全封装。当前只接入 tree-sitter native 与 plain，**不接入 regex / TextMate scope 引擎**。

| Provider 形态 | 触发模型 | 增量能力 | 失败模式 |
|---|---|---|---|
| tree-sitter（native，Tier 1） | 后台 worker 处理 `on_edit` | 内部 `InputEdit` + `Parser::parse_with_options(.., Some(&old))` | parse 失败 / 翻译失败 / 版本不连续：回退全量 `run_full` |
| tree-sitter（wasm，Tier 2 语言包） | 后续接入 | 同上 | 同上；额外：装载失败 / ABI 不匹配 → 整体落 plain |
| LSP semantic tokens | `on_edit` 只更新内部版本号 | 协议 `SemanticTokensDelta`；首次全量 | server 未就绪 / 超时 / 协议错：保持 slot 不动；不主动清空 |
| plain（占位） | 永远不写 slot | — | — |

native 与 wasm 两种 tree-sitter provider 对调度层透明——同一 trait、同一 slot 契约，差异封装在 provider 实现内部（详见 §十）。

**所有 provider 必须遵守**：

- `attach` / `on_edit` 调用结束后通过 `export_syntax_tree(&slot)` 把内部状态导出；**不在 trait 方法外另起一条投递路径**。
- `detach` 调用返回后**绝不再写 slot**。异步 provider 内部需要在自己的 task 里检查 detach 标记。
- 不在 trait 方法内做阻塞 IO；需要 IO 的 provider 自起 task。
- 产出的 name 必须落在 tree-sitter highlight name 命名空间内（LSP provider 在内部做映射）。

## 九、生命周期

```text
open_file(path)
    │
    ▼
workspace 创建 Buffer + BufferId
    │
    ▼
BufferSyntax::attach
    │  language = registry.detect(path, first_line)
    │  provider = registry.make_provider(language)
    │  worker.attach(buffer_id, provider, snapshot, slot.clone())
    ▼
worker: provider.attach → provider.export_syntax_tree(&slot)
    │
    ▼
buffer 编辑 → BufferSyntax::handle_edit
    │  主线程：slot.try_edit(input_edits, new_snapshot, new_version)
    │  异步：worker.edit(buffer_id, changeset, new_snapshot, new_version)
    │
    ▼
worker: provider.on_edit → provider.export_syntax_tree(&slot)
    │
    ▼
编辑面 re-render（paint 端 slot.load() → query_viewport → Decoration）

──── 切换语言 ────
BufferSyntax::detach → slot.clear() → worker.detach(buffer_id) → 新 attach

──── 关闭 buffer ────
BufferSyntax::detach → slot.clear() → worker.detach(buffer_id)
```

**不变量**：

- 任意时刻每个 `BufferId` 最多挂一个 provider。
- `detach` 后 slot 必为空；切换语言不允许「旧 tree 残留 + 新 tree 叠加」。
- buffer 未挂 provider 时 slot 不存在（`syntax_tree_slot()` 返回 `None`）；渲染层不能假设它一定存在。

## 十、可插拔机制与语言规模

「内置几种」只能撑到 ~20 门语言；超过后会同时撞二进制体积、CI 时间、发版耦合三堵墙。为兼顾「常用语言开箱即用」与「长尾语言不拖体积」，语法接入分两层。

### Tier 1：内置语言（compile-in）

- 范围：zom 保证开箱可用的核心集（约 15–25 门，具体清单由主仓维护）。
- 交付：tree-sitter grammar 与对应 provider 作为普通依赖直接编进 `zom-workspace`，启动期在组合根遍历内置 provider 调 `registry.register(...)`（见 [`install_builtin_providers`](../../zom-workspace/src/syntax/providers/mod.rs)）。
- 准入维度：使用频率、grammar 上游稳定度、对二进制体积的影响。
- LSP provider 同属此层（按 workspace 配置连接对应 language server）。

### Tier 2：语言包（WASM，on-demand）

- 范围：Tier 1 之外的全部 tree-sitter 语言。
- 交付：每门语言独立打包为「语言包」，runtime 通过 tree-sitter 官方 WASM runtime 装载。**不**采用 dylib——跨平台分发、沙箱隔离、零用户侧工具链依赖三项综合下来 WASM 是更合理的默认；性能损失（约 native 2–3×）在桌面端 syntax 高亮场景可接受。
- 对调度层透明：registry 工厂闭包返回 `Box<dyn HighlightProvider>`，内部是 native tree-sitter 还是 wasm tree-sitter 不外露；trait / slot / worker 完全不区分。
- 用户路径：打开未识别文件 → workspace 上报未知扩展 → 状态栏建议安装语言包 → 用户确认后装入 → registry 注册新工厂 → 已打开 buffer 触发重新 detect & attach。

### 语言包格式

最小内容：

```text
<pack-id>/
  pack.toml          # id / display name / version / ts-abi-version / detectors
  grammar.wasm       # tree-sitter parser 的 wasm 产物
  queries/
    highlights.scm
```

- `ts-abi-version` 必须与 zom 内嵌的 tree-sitter wasm runtime ABI 匹配；不匹配则装载失败，该语言落 plain。
- `detectors` 与 §六 `LanguageDetector` 同构，pack 自描述识别规则。
- 其余 query 文件（`locals.scm` / `injections.scm` 等）第一版忽略，留作未来扩展。

### Queries 与 grammar 解耦（不变量）

无论 grammar 是 Tier 1 内置还是 Tier 2 wasm，**queries 永远允许被外部资源覆盖**：

- 查询查找顺序：用户配置目录 > 语言包内 `queries/` > Tier 1 内置默认。
- 收益：修高亮规则不需要发 zom 版本，也不需要重发语言包。
- Grammar 二进制是另一维：Tier 1 随 zom 发版，Tier 2 随语言包独立发版。

### 装载器接口

```rust
pub trait LanguagePackLoader: Send + Sync {
    fn list_installed(&self) -> Vec<InstalledPack>;
    fn load(&self, pack_id: &str) -> Result<Box<dyn HighlightProvider>, LoadError>;
}
```

- 装载器在组合根注入 registry，与 Tier 1 的内置 provider 工厂在 registry 内并列。
- 包的获取、缓存、签名校验、版本升级、磁盘存放路径都是装载器内部职责，不在本手册规定。
- `registry.register` 已经只接 `Box<dyn HighlightProvider>` 工厂，本接口加入不破坏既有签名。

### 不在本手册规定的事

- 语言包的**分发渠道**（仓库 URL / 镜像 / 签名信任锚）——属发行工程范畴，单独成文。
- 语言包的**作者工作流**（从 tree-sitter grammar 源码产出符合本格式的 pack 的流程）——单独写作者手册。
- 包管理 UI（安装 / 卸载 / 升级界面）——desktop 端 UX 章节。

## 十一、与渲染契约的对接

本手册只规定 syntax producer 把产物存到哪里、以何种形态存。**多 producer 的合成、叠加规则、优先级档位不在本手册**——全部在 [`桌面端高亮架构.md`](桌面端高亮架构.md)。

对接点：

1. worker 把 reparse 后的 `Arc<BufferSyntaxTree>` 写共享 [`BufferSyntaxTreeSlot`]；主线程 `BufferSyntax::handle_edit` 同步推进 slot 里 tree 的字节坐标，让 paint 当帧拿到的 tree 已对齐新 snapshot。
2. paint 端从 [`WorkspaceBuffer::syntax_tree_slot`] 拿 slot，`load()` 出 `Arc<BufferSyntaxTree>`，调 [`BufferSyntaxTree::query_viewport`] 在当前 viewport 字节区间上跑 tree-sitter Query，返回 `(TextRange, HighlightSpan)` 列表。
3. desktop 端 syntax producer（[`zom-desktop::editor::highlight::producers::syntax`](../../zom-desktop/src/editor/highlight/producers/syntax.rs)）把每条 span 翻译成一条 `Decoration { kind: Foreground, style: theme(name + modifiers), priority: SYNTAX_CONFIRMED }`，进入 composer。
4. theme 端按完整 name → 点分前缀 → 默认前景色逐级回退查询（**回退链是本子系统的不变量**）。theme 查表逻辑统一抽到 desktop `shared/theme.rs`；theme 内容对齐 tree-sitter 生态（Helix / Zed 兼容口径），不在本手册定义。
5. **`QueryCursor` 复用**：tree-sitter 的 `QueryCursor` 构造一次还行，每帧若干次会累积分配。渲染端在 thread-local 上持一份 [`SyntaxQueryCursor`]，每帧 paint 时借给 `query_viewport`（见 [syntax producer](../../zom-desktop/src/editor/highlight/producers/syntax.rs)）。

字符背景（搜索高亮 / 选区）会盖在 syntax 字色之上的 cell，但 syntax 字色仍生效——`Foreground` 与 `Background` 在 composer 内正交（详见高亮架构 §五）。

## 十二、降级与边界条件

| 触发条件 | 调度层行为 |
|---|---|
| `registry.detect` 命中 `plain` | 不创建 provider；slot 不存在 |
| `registry.make_provider` 返回 `None`（Tier 2 包未安装） | 同上；可由 UI 层提示「装语言包」 |
| Tier 2 语言包装载失败（ABI 不匹配 / 文件损坏 / grammar.wasm 缺失） | 装载器返回 `LoadError`，registry 不注册该语言；落 plain |
| 文件大小 > `MAX_HIGHLIGHT_BYTES`（16 MiB） | 不 attach；状态栏可显示「高亮已停用」 |
| tree-sitter provider panic（native 或 wasm） | worker `catch_unwind` 捕获 → 丢弃 entry → 该 buffer 退化为 plain；其他 buffer 不受影响 |
| LSP server 未就绪 / 超时 / 协议错 | 保持 slot 不动；不主动清空 |
| 用户手动切换语言 | detach old → slot 清空 → attach new |
| Buffer 关闭 | detach → slot 清空 |
| theme 未命中某 name | 走点分前缀回退，最终落默认前景色——**不算错** |

`MAX_HIGHLIGHT_BYTES = 16 MiB` 集中维护在 [`coordinator.rs`](../../zom-workspace/src/syntax/coordinator.rs)；不允许 provider 内部各自设阈值。

## 十三、首帧不变量

**结构未变的小编辑下，edit 后立即 paint 的 syntax decoration 必须等于 worker reparse 完成后的 paint 结果**——这条不变量决定了 token 内插入不会闪默认前景色，由两件事保证：

1. 主线程同步 `slot.try_edit`：克隆当前 tree、按 `InputEdit` 推坐标、写回 slot。这一份 interpolate tree 字节坐标已对齐新 snapshot。
2. paint 端按 viewport 现查 `query_viewport`：tree 在 viewport 内的 node 范围与新 snapshot 对齐，query 命中扩展后的 token 节点。

测试钉死：

- [`syntax::providers::common::tests::incremental_matches_full_after_edits`](../../zom-workspace/src/syntax/providers/common.rs)：增量 spans ≡ 重 parse 后的全量 spans。
- [`zom-desktop::app::tests::edit_immediately_extends_syntax_decoration_inside_heading_token`](../../zom-desktop/src/app/mod.rs)：token 内插入后立即 snapshot，decoration 必须覆盖新字节。
- [`zom-desktop::app::tests::edit_frame_decorations_equal_reparse_frame_for_structure_preserving_edit`](../../zom-desktop/src/app/mod.rs)：edit-frame ≡ reparse-frame。

结构变更的编辑（如 `fn` → `fnx`）仍有"先以旧 token 类型显示、worker reparse 回包后纠正"的几帧色跳——tree-sitter 增量 reparse 自身代价（16 MiB rust 单键 p99 ≈ 58 ms，详见 [BASELINE](../../zom-bench/BASELINE.md) §2.1），不可绕过。小文件上可叠加"命中预算就同步 reparse"的 fast-path 消掉这点，作为可选优化。

## 十四、测试要求

| 模块 | 测试形态 |
|---|---|
| `LanguageRegistry::detect` | 纯函数表驱动：extension / shebang / mode-line / filename 各类输入决定性 |
| `BufferSyntaxTreeSlot` 版本守护 | `store_if_newer` 给定 stale / current / future version 三种推入，断言「丢弃 / 落地」 |
| `BufferSyntax` 生命周期 | attach / detach 配对：detach 后 slot 必为空；切换语言不残留旧 tree |
| 共享 worker 串行 | mock provider 计数器验证 attach / edit / detach 各回调次数 |
| Provider 实现 | 在 provider 自己的模块内单测（参考 rust / markdown），trait 层用 mock provider |
| 首帧不变量 | 见 §十三 |
| theme 回退链 | 未命中完整 name → 命中前缀；未命中前缀 → 默认前景色；绝不缺省 |

**不测**：

- engine 自身行为（engine 自己有覆盖）。
- tree-sitter / LSP 上游正确性（外部已验证）。
- GPUI 渲染像素结果（由 desktop 端 element 测覆盖，见 [`桌面端组件实现.md`](桌面端组件实现.md) §一.11）。

## 十五、当前不做的事

明确划掉，避免范围漂移：

- **自研高亮算法**：包括 regex / TextMate scope 引擎在内的任何「我们自己写词法」路径，不接入、不留口。
- **自有 token 词汇表**：name 一律走 tree-sitter 命名空间，不另起。
- **dylib 形态的 Tier 2 装载**：Tier 2 只走 WASM，不并行支持 dylib。
- **多 provider 叠加**：tree-sitter + LSP 合成的双层产出。
- **跨语言嵌入（injection / combined parsers）**：通用机制不做，**markdown 是被纳入手册的唯一特例**，仅此一例。
  - `BufferSyntaxTree` 已扩成 `Vec<SyntaxLayer>` 多层容器（每层 = 一份 `Arc<SharedConfig>` + `Tree`）；paint 端 `query_viewport` 对每层独立跑 query 后用 `overlay_layers` 按 precedence 自下而上合并（上层在覆盖区间内胜出）。非 markdown 语言全程 `layers.len() == 1`，走单层快路径，代价等同单 tree 时代。
  - **markdown 例外**接入：
    - block grammar + inline grammar 的主从配对（`tree_sitter_md::LANGUAGE` + `INLINE_LANGUAGE`），让 `**bold**` / `*italic*` / `` `code` `` / `[link](url)` 出 inline 着色；
    - fenced code 注入（` ```rust ... ``` `）：fence info-string 按 [`injection::resolve_injection_language`](../../zom-workspace/src/syntax/providers/injection.rs) 查表落到 Tier 1 内置语言（rust / py / ts / sh / yml ...，带常见别名），未命中语言保持 block grammar 的 `markup.raw.block` 兜底。
    - 注入失败仅丢失败的那条 fence，不牵连其余 fence / inline / block。
    - 实现封装在 [`syntax::providers::markdown`](../../zom-workspace/src/syntax/providers/markdown.rs) 内部，不污染通用 [`HighlightWorker`]。
  - **仍不做**：
    - tree-sitter-md 的 `html_block` / frontmatter / 递归 markdown 注入；
    - markdown 之外的语言注入（HTML 内 JS / CSS、TypeScript 模板字符串内 SQL 等）——新语言要做注入必须先在手册写新一条例外，不开自动通道。
- **运行时切换 wasm runtime 版本**：ABI 版本随 zom 编译期固定，包不匹配即拒绝装载。
- **主线程同步 reparse**：单字符 reparse 在 16 MiB 上 p99 ≈ 58 ms，必须留在 worker。小文件 fast-path 是可选优化项。
- **缓存 viewport spans**：paint 端按 viewport 现查（p99 < 100 µs），不引入「viewport spans cache」抽象。
- **语言包的分发渠道 / 作者工作流 / 包管理 UI**：均在本手册范围外，各自单独成文。
- **mini-map / 缩略图的语法着色**（与 mini-map 一起推迟）。
- **token 自定义 modifiers 的运行时扩展**：modifiers 在编译期定 bitset。
