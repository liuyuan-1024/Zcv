# 可见性清理

目标是让每个跨模块符号只有一条符合职责的规范访问路径，并把实现细节收回最窄可见范围。执行前读取 `docs/重导出规范.md`；若仓库当前实现与文档不一致，先判断是实现偏离还是文档已经过时，不用文档机械覆盖代码。

## 建立清单

对目标 crate 或能力域逐项确认：

1. 符号定义位置与当前可见性。
2. 门面中的 `use`、`pub(crate) use`、`pub use` 和模块可见性。
3. 能力域外的真实消费方及其导入路径。
4. 测试是否是唯一消费方。
5. 是否同时存在实现路径、门面路径或兼容路径。

Rust library crate 的 crate 根是 public API 门面；binary crate 内部能力域通常使用 `pub(crate)` 门面。先识别 crate 性质，不把两者混为一谈。

## 重点查找

- `pub mod` 或 `pub(crate) mod` 公开实现模块，同时又重导出其中符号。
- 消费者穿透私有能力域应有的门面，直接依赖物理文件路径。
- 通配符重导出，或没有能力域外真实消费者的公开符号。
- 根模块只供自己使用，却通过公开重导出引入的符号。
- 为旧内部路径保留的别名、转发模块或双轨入口。
- 仅为测试扩大生产可见性的 helper。
- trait、handle、event 等一组契约从不同门面泄漏。
- 上游协议类型被无意义地经过多个 crate 重导出。

## 决策规则

- 实现子模块默认私有；只有模块命名空间本身是跨域契约时才公开模块。
- 有能力域外真实消费者时，从最近的职责门面选择性重导出；否则保持私有导入。
- 同一符号只保留一条规范跨域路径。更新所有调用方后直接删除旧路径，不增加兼容转发。
- 类型应留在职责匹配的叶子模块，门面只决定访问路径；不要用重导出掩盖错误归属。
- 同文件测试访问私有实现，不为测试扩大生产接口；跨模块测试入口必须确有必要并受 `#[cfg(test)]` 限定。
- 不用 `#[allow(unused_imports)]` 或其他 Lint 抑制隐藏错误门面。

## 修改与验证

修改时按一个完整批次完成：收紧模块或符号可见性、更新消费者到规范路径、删除旧入口、清理失效导入，并同步受影响文档。

验证至少包括：

- 搜索旧路径、旧别名和重复重导出已经消失；
- 对受影响 crate 运行编译检查，利用编译器发现遗漏消费者；
- 对改变 public API 或关键装配路径的部分运行相关测试；
- 运行格式和必要的 Lint 检查，不用警告抑制换取通过。

报告应列出收紧了哪些边界、保留的唯一规范路径，以及是否仍有未处理的外部兼容要求。
