# 数据目录规范

Zcv 的用户级持久化数据统一位于 `zcv-settings::config_dir()` 返回的目录。当前桌面环境中该目录是用户主目录下的 `.zcv`。

业务模块必须从这一入口派生路径，不自行读取主目录环境变量或复制配置根路径算法。

## 当前布局

```text
~/.zcv/
├── settings.json
├── recent_projects.json
├── window_bounds.json
├── workspaces/
└── updates/
```

- `settings.json`：用户设置，由 `zcv-settings` 读取、合并和监听。
- `recent_projects.json`：最近项目，由 `zcv-workspace` 管理。
- `window_bounds.json`：窗口位置和尺寸，由 `zcv-workspace` 管理。
- `workspaces/`：按项目身份保存的 Pane、Dock 与 Panel 可恢复布局。
- `updates/`：更新暂存、事务、启动确认和最近结果。

## 规则

- 每类数据只有一个负责读写的模块，其他模块通过其 API 使用。
- 文件路径从 `config_dir()` 逐级派生，不接受任意外部路径替代受控事务目录。
- 持久化格式只保存稳定、可恢复的事实，不保存运行时 `Entity`、句柄或可重建缓存。
- 写入失败必须在最接近所有者的位置报告；不能静默切换到另一份数据源。
- 格式变更若没有明确外部兼容要求，直接更新读写方和测试，不长期维护新旧双轨格式。

新增持久化数据时，应在本文件补充目录用途，并在所有者模块中集中定义路径与读写协议。
