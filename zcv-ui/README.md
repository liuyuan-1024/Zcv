# zcv-ui

`zcv-ui` 是 Zcv 的设计系统与基础展示组件层。它统一稳定的视觉语义和可复用交互原语，不承载编辑器、工作区或具体业务模块的状态。

公共入口是 [`src/ui.rs`](src/ui.rs)。未从该入口重导出的模块属于 crate 内部实现。

## 收录边界

组件进入 `zcv-ui` 前，应先确认存在两个或更多真实消费方：

- 单一消费方使用的控件留在消费方附近。
- 多个消费方共享的按钮、图标、标签、列表项、滚动条或提示可以下沉为基础组件。
- 业务命令、项目状态和文档状态不因“带 UI”而进入设计系统。
- 不为潜在复用预建通用组件或配置接口。

## 组件形态

根据生命周期选择最小形态：

- 简单且无独立状态的局部结构使用普通函数或元素组合，并留在消费方模块。
- 可复用、可配置、一次性渲染的基础组件使用 Builder 风格 API 与 `RenderOnce`。
- 只有需要跨帧身份、订阅、任务、焦点或外部更新时，才使用 `Entity`。

不要为了统一外观强迫所有组件采用同一种形态。组件的状态所有权应能从构造方式和 API 看出来。

## 设计规则

- 尺寸、间距、颜色和文字优先使用 `zcv-theme` 的设计令牌。
- 共享组件表达视觉与交互语义，调用方负责业务决策。
- Builder 方法只暴露真实需求；默认值由组件显式确定。
- 回调和订阅的生命周期与组件一致，不使用隐藏的全局注册维持状态。
- 公共 API 保持小而明确，内部组合细节不重导出。

## 编辑器输入反转

设计系统中的输入能力通过 `EDITOR_FACTORY` 获取类型擦除的编辑器接口。工厂由 `zcv-editor::init` 填充，因此依赖方向保持为：

```text
zcv-editor ──提供实现──> zcv-ui::EDITOR_FACTORY
zcv-ui      不依赖      zcv-editor
```

这个接口只保留基础输入所需的文本、占位符、焦点、编辑事件与渲染能力。不要把完整编辑器 API 扩散到设计系统。

## 验证

```bash
cargo check -p zcv-ui
cargo test -p zcv-ui <相关测试过滤条件>
```
