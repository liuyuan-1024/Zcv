# 重导出规范

> 规定 zcv crate（binary crate）中 `pub use` / `pub(crate) use` 的使用原则，参考 Rust API 指南、Zed 及生态实践。

---

## 一、背景

`pub use`（重导出）是 Rust 中组织模块可见性的核心工具。它将一个路径下的符号"重新导出"到当前位置，从而**解耦内部模块组织与外部可见路径**。

对于 library crate，重导出属于 semver 承诺（[C-REEXPORT](https://rust-lang.github.io/api-guidelines/)）。对于 binary crate（如 zcv），虽然没有外部 API 约束，但合理的可见性策略可以减少 import 噪音、避免路径混乱，是代码健康度的一部分。

---

## 二、Rust 生态惯例

| 来源 | 核心主张 |
|------|---------|
| **Rust API 指南 (C-REEXPORT)** | 常用功能应在 crate 根级重导出，不常用的留在模块路径 |
| **Tokio** | 根级只提核心函数（`spawn`），其余走模块路径；条件编译门控 |
| **Zed** | `mod.rs` 选择性展平关键类型；既保留模块路径也提具体类型 |
| **rust-analyzer 指南** | 避免重导出 —— 一个类型两条路径是混乱的源头 |

zcv 采用保守务实的策略：**优先直接暴露模块路径，不额外做重导出层。**

---

## 三、zcv 重导出规则

zcv 是 **binary crate**，所有可见性面向 crate 内部。统一使用 `pub(crate)`，不使用 `pub`。

### 规则 1：子模块一律 `pub(crate)`，`mod.rs` 不做重导出

```rust
// ✅ 当前做法：子模块直接开放
pub(crate) mod dock;
pub(crate) mod pane;
pub(crate) mod status_bar;

// 消费者通过模块路径导入
use crate::workspace::dock::LayoutController;
use crate::workspace::pane::Pane;
use crate::workspace::status_bar::StatusBar;
```

等价于"一个类型只有一个规范路径" —— 不存在两条路径指向同一类型。

### 规则 2：不跨模块重导出

类型定义在哪个模块，就从哪个模块导入。不在 `mod.rs` 中额外"转发"一遍。

```rust
// dock.rs 中定义了 LayoutController、PaneGroup 等
// 消费者直接：
use crate::workspace::dock::LayoutController;
use crate::workspace::pane::Pane;

// 而不是通过 mod.rs 中转：
// use crate::workspace::LayoutController;   // ❌ 不需要这层重导出
```

### 规则 3：`mod.rs` 只做两件事

- 声明子模块并决定其可见性（`pub(crate) mod` / `mod`）
- 跨子模块共享的内部类型（用 `use` 导入，不 `pub use`）

```rust
// workspace/mod.rs —— 同时定义 Workspace struct 并声明子模块
// （Zed 模式：Workspace 是模块根而不是子模块）
pub(crate) mod dock;
pub(crate) mod pane;
pub(crate) mod project_tree;
pub(crate) mod status_bar;
mod recent_projects;   // 仅在 workspace 内部使用，保持私有
```

### 规则 4：仅在叶子模块定义类型

不要让 `mod.rs` 定义类型以外的顶层内容。类型定义下放到具体子模块文件中。

```rust
// workspace/dock.rs  —— ✅ 在这里定义 LayoutController、PanelEntry
// workspace/mod.rs    —— ❌ 不在这里定义子模块的类型（Workspace struct 自身除外）
```

### 规则 5：内部模块保持私有

仅在同一个模块树内部使用的模块，保持 `mod` 私有。

```rust
mod recent_projects;  // 只被 workspace 子模块引用，对外不可见
```

---

## 四、这样做的收益

| 做法 | 问题 |
|------|------|
| `mod.rs` 做 `pub use` 重导出 | 每个新类型要加一行，消费者有两条路径可达 |
| 子模块直接 `pub(crate) mod` | 一条路径直达，新增类型无需额外操作 |
| 在 `mod.rs` 定义类型 | 类型位置和模块路径不一致，查定义需要跳两次 |

**当前模式：** 所有 `pub(crate)` 子模块，`mod.rs` 零重导出，类型定义即路径。

---

## 五、例外情况

### 5.1 action 模块

`actions!` 宏生成的 action 类型（如 `ToggleProjectTree`、`GitFetch`）是模块内的零散类型，没有"主类型"可展平。这类模块也按规则 1 处理：直接 `pub(crate) mod`，外部通过模块路径引用。

```rust
use crate::workspace::dock::ToggleProjectTree;
```

### 5.2 测试可见性

测试需要访问的私有项，用 `#[cfg(test)]` 包裹：

```rust
#[cfg(test)]
pub(crate) fn helper_for_test() { ... }
```
