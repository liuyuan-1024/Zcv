# 编辑器架构迁移与验证

用于已经明确授权的实现、迁移、重构或修复。成功标准是建立 `docs/编辑器架构.md` 规定的唯一正确边界并迁移全部受影响调用方，不是让局部用例暂时通过。

## 修改前确定目标

先完成审计参考中的事实图，并写清：

- 本次涉及的架构层与稳定不变量编号；
- 当前错误的权威状态、坐标、增量或生命周期路径；
- 修改后的唯一所有者、快照、坐标类型、同步入口和依赖方向；
- 哪些旧类型、字段、事件、刷新路径、缓存或适配层会被替代并删除；
- 哪些产品能力明确不在本次范围内。

检查工作树并保留用户已有修改。架构文档和第 18 节差距登记可能含用户的未提交编辑；不得覆盖或回退。

## 实施原则

1. 从最低受影响层建立正确契约，再逐层迁移到消费方。
2. 每个事实只保留一个可写所有者；派生快照和缓存经唯一入口整体替换。
3. 新增或修正坐标空间时同时完成 newtype、正反转换、边界语义、失败语义和跨版本测试。
4. 新增或修正快照时同时处理文本版本、元数据版本、下层同版本固化和过期结果拒绝。
5. 新增或修正增量层时同时提供下层 edit 消费、本层 edit 产出、cursor/iterator 读取和结构重建后的 Anchor 重解析。
6. 修改事务时保持单一写入路径和“文本 → 显示 → 选择”顺序；空事务不推进历史或事件。
7. 修改订阅或异步任务时明确唤醒者、状态推进者、取消时机、版本校验和结果安装入口。
8. 一次性更新全部静态调用方、行为测试和受影响文档，随后删除旧状态、旧入口、fallback、兼容层和双轨分支。
9. 只删除本次目标边界替代的概念，不借迁移清理无关代码。

如果迁移需要临时中间态，只能存在于当前工作过程，最终 diff 不能把它作为长期架构提交。不要用 feature、别名、转发器或“稍后清理”保留旧路径。

## 分层验证

选择能直接证明目标不变量的最小测试，不运行全量测试。

- 文本层：版本失配、事务原子性、净编辑、历史可见性、跨版本与跨代际 Anchor、undo/redo、保存点、每消费者批次。
- 语言层：文本/语法同版本、插值版本与解析版本、过期结果拒绝、单解析任务、注入补解析、元数据版本推进。
- 组合层：excerpt 排序与尾部换行、源/组合/diff 坐标、连续 cursor、结构重建后 Anchor 重解析、文本与纯元数据同步、多源事务身份。
- 显示层：Fold/Tab/Wrap/Block 正反转换、显式 Bias、逐层 edit 传播、变换树覆盖、折叠/换行/虚拟块组合、异步 Wrap 插值收敛、热路径按需读取。
- 交互层：所有文档形态共用事务入口、选择唯一入口、编辑后选择落位、输入法、滚动 Anchor、undo/redo 选择恢复、真实事务事件、只读复用同一管线。
- 渲染层：同版本快照、可见范围读取、像素命中、缓存失效、不写回权威、不物化整份投影文本。
- 工程边界：同路径/修订实体复用、弱引用生命周期、Project 不依赖组合文档、Workspace 不复制 Item 状态。

除行为测试外，按修改范围运行：受影响 crate 的编译或类型检查、格式检查、必要的定向 Lint。性能或内存不变量若受影响，应增加与热路径直接相关的基准或分配证据；宽泛编译通过不能证明增量协议、坐标语义或生命周期正确。

## 迁移完成检查

- 搜索旧类型、旧字段、旧入口、旧事件和兼容路径，确认只剩目标架构的规范路径。
- 从一个代表性动作重新追踪完整数据流，确认各层只消费直接下层并向上产出增量。
- 检查所有长期位置都使用 Anchor，所有裸坐标都有明确快照与空间。
- 检查文本和非文本变化都能推进一致快照链，且过期后台结果不能安装。
- 检查第 18 节：消除的差距删除，新增且未在本次解决的真实差距登记；不要记录实施历史。
- 检查相关 README、架构文档、注释和测试只描述当前有效行为。
- 检查 diff 不包含无关格式化、重命名或清理，也没有警告抑制。

交付时以“不变量 → 代码证据 → 验证结果”报告。环境限制、未运行的平台验证和未覆盖的运行时行为必须单独列出，不能描述为已通过。
