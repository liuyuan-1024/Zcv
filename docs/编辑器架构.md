# Zcv 编辑器目标架构

> 本文定义 Zcv 编辑器核心的目标架构：各层职责、状态所有权、数据流、生命周期、依赖方向与长期不变量。
> 它不是源码导读，不逐文件说明，也不记录普通函数和类型成员。只有「不写下来就可能出现多种看似合理、但会导致架构逐渐分叉的实现方式」的内容才进入本文。
> 架构原型是 Zed 编辑器。Zcv 明确不引入实时协作、远程开发与 LSP；对应能力及其专属基础设施被裁掉，裁剪后剩余的架构契约与原型保持同方向。
> 判断某个设计是否偏离本文的依据是职责边界、状态所有权、依赖方向、数据流与不变量，而不是文件名或代码形状。

---

## 1. 定位、原型与裁剪边界

### 1.1 目标原型

Zcv 编辑器核心的目标形态，是「去掉协作、远程、LSP 之后仍然成立的 Zed 编辑器架构」。因此：

- 凡是在原型中承担编辑器核心职责、且对 Zcv 仍然有意义的抽象，默认完整复刻，而不是重新设计；
- 「Zcv 现在没有」不等于「Zcv 不需要」，它只是尚未复刻；
- 只有当某项架构的根本存在理由就是协作、远程或 LSP 时，才允许随之删除或简化；
- 删除能力时只做由能力缺失直接导致的调整，不借机重塑剩余架构。

### 1.2 明确舍弃的能力

当前阶段 Zcv 明确不引入：

- 实时协作：CRDT 副本合并、远程编辑、协作者光标与选择广播、跟随者、协作会话；
- 远程开发：远程工作区、远程路径、远程缓冲区传输、参与方协商；
- LSP：语言服务器客户端、语言服务器 Store、服务器诊断、服务端 semantic token、代码操作、hover、服务器生命周期。

这些能力只能在能力与职责层面裁剪，不能机械地按模块或文件删除。一个抽象若同时服务于编辑器核心和上述能力，必须剥离不需要的部分、保留核心职责与边界。

当前阶段暂不实现的编辑能力：

- 多光标交互状态，包括多个选择的分组、选择下一个／上一个匹配以及列选择。

这属于产品范围限制，不改变目标架构。未来如果实现，必须扩展 `Editor` 的选择集合、`TransactionId` 历史关联、输入法、自动闭合、命令分发和渲染边界，不能建立第二套编辑流程。

### 1.3 偏离本文的判定

允许的偏离只有两类：

1. 能明确追溯到 Zcv 已舍弃能力的裁剪；
2. 架构语义一致、仅实现技术不同的实现差异。

不允许以「当前实现更简单」「Zcv 规模更小」「改动较大」「某个抽象目前只有一个使用者」「可以想到更直接的写法」为理由偏离。若当前实现与本文冲突，当前实现应被识别为待修正的差距。

### 1.4 本文效力

本文是编辑器核心的架构契约。新增或修改编辑器能力时：

- 先判断它属于哪一层、由谁拥有状态、沿哪条数据流传播；
- 若现有边界无法容纳，应先修正抽象，再把全部调用方迁移到新边界；
- 不保留新旧双轨、兼容层、隐式回退或一次性旁路。

## 2. 分层与唯一数据流

### 2.1 分层

Zcv 编辑器核心自底向上分为六层，每层只依赖其下层：

~~~text
┌──────────────────────────────────────────────────────────────┐
│ 应用装配／工作区          zcv、zcv-workspace                   │
│ 窗口、Pane、Dock、Item、持久化、命令分发                       │
├──────────────────────────────────────────────────────────────┤
│ 渲染与命中                EditorElement                        │
│ 逐帧行布局、文本 shaping、像素命中、光标与装饰绘制             │
├──────────────────────────────────────────────────────────────┤
│ 交互与事务编排            Editor                              │
│ 选择、滚动、输入法、搜索、折叠、鼠标手势、事务、事件           │
├──────────────────────────────────────────────────────────────┤
│ 显示投影                  DisplayMap                          │
│ Fold → Tab → Wrap → Block，显示坐标与显示快照                  │
├──────────────────────────────────────────────────────────────┤
│ 组合文档                  MultiBuffer                         │
│ excerpt 顺序、组合坐标、diff 投影、组合事务与订阅              │
├──────────────────────────────────────────────────────────────┤
│ 语言快照                  LanguageBuffer                      │
│ 直接持有文本与 Tree-sitter 语法状态、查询、语言设置            │
├──────────────────────────────────────────────────────────────┤
│ 文本事实                  Buffer（由 LanguageBuffer 持有）     │
│ 文本存储、版本、事务、编辑日志、历史、Anchor                   │
└──────────────────────────────────────────────────────────────┘
~~~

各层一句话职责：

- 文本事实层（`zcv-text`）：唯一拥有文本内容、版本、编辑事实与撤销历史。
- 语言快照层（`zcv-language`）：直接持有文本 `Buffer` 与 Tree-sitter 语法状态，提供一致快照与语法查询。
- 组合文档层（`zcv-multi-buffer`）：把若干源文档组织为一个组合文档，拥有 excerpt 顺序、组合坐标与 diff 投影。
- 显示投影层（`zcv-editor::DisplayMap`）：把组合文档投影为可显示的文本拓扑，拥有折叠、tab、软换行与虚拟块。
- 交互层（`zcv-editor::Editor`）：拥有选择、滚动、输入法、搜索、折叠状态等交互状态，并编排编辑事务。
- 渲染层（`zcv-editor::EditorElement`）：只负责当前帧的布局、绘制与命中测试，不写回文档事实。

### 2.2 唯一数据流

~~~text
zcv-text::Buffer ──Snapshot / Edit / Patch / Anchor / TransactionId
        ▲ 直接持有
        │
zcv-language::LanguageBuffer ──LanguageBufferSnapshot（文本 + 语法同版本）
        │
        ▼
zcv-multi-buffer::MultiBuffer ──MultiBufferSnapshot / MultiBufferAnchor / Projection Edit
        │
        ▼
zcv-editor::DisplayMap ──DisplaySnapshot（逐层嵌套的显示快照）
        │
        ▼
zcv-editor::Editor ──选择 / 滚动 / 输入 / 事务 / 事件
        │
        ▼
zcv-editor::EditorElement ──逐帧布局与绘制
~~~

两条硬性规则：

1. 状态只沿上述方向被下层拥有、被上层消费；上层不得把自己的状态下沉为下层的权威。
2. 变化只沿上述方向以「旧快照 + 增量」传播；上层不得通过物化整份文本或重算整份投影来获得变化。

传播语义的补充约束：

- 文本内容变化采用「已变化标记 + 按版本拉取」：源文档只记录自己已变化，组合文档在读取时按源版本差拉取净编辑，不在每次源编辑时立即重建。
- 每个投影层消费其下层的增量、转换成本层增量，并固化下层同版本快照；显示快照是整条链的叶，渲染只读它。
- 组合文档对外同时发布粗粒度语义事件与细粒度输出偏移增量：前者驱动语义刷新，后者让选择与显示缓存增量平移。

### 2.3 单一 Editor 管线

普通文件、搜索结果、Git 差异、预览派生等所有文档形态共用同一个 `Editor` 与同一套选择、滚动、输入、编辑、折叠、命中测试和渲染管线。文档形态只能通过以下位置表达差异：

- `MultiBuffer` 的源 excerpt、路径顺序与可编辑性；
- diff 投影的虚拟内容与 hunk 身份；
- `DisplayMap` 的 block、fold 与布局参数；
- `Editor` 的构造入口与只读策略。

禁止按文档形态复制 `Editor`、复制编辑流程，或在普通文档与组合文档之间维护平行的交互状态。

## 3. 状态所有权与权威数据源

### 3.1 权威数据源总表

| 事实 | 唯一所有者 | 其他层的形式 | 生命周期 |
| --- | --- | --- | --- |
| 源文本内容、版本、事务历史、编辑日志 | `zcv-text::Buffer` | 不可变 `Snapshot`、`Edit`/`Patch`、`Anchor`、`TransactionId` | `Buffer` 由 `Project` 的文件边界创建；编辑会话围绕它展开 |
| 文本与 Tree-sitter 语法的一致状态 | `zcv-language::LanguageBuffer` | `LanguageBufferSnapshot`、`SyntaxSnapshot`、查询结果 | 自身直接持有文本 `Buffer`，随文档实体创建与销毁；解析任务随它创建与取消 |
| excerpt 顺序、路径身份、组合坐标、diff 投影 | `zcv-multi-buffer::MultiBuffer` | `MultiBufferSnapshot`、`MultiBufferAnchor`、投影增量 | 由 `Editor` 或工作区持有；可包含一个或多个源文档 |
| 折叠、tab、软换行、虚拟块 | `zcv-editor::DisplayMap` | `DisplaySnapshot` 及各层 `Snapshot` | 由 `Editor` 创建并持有；编辑器关闭即销毁 |
| 选择、选择历史、滚动、输入法、搜索、折叠开关、鼠标手势 | `zcv-editor::Editor` | `EditorEvent`、当前帧读取的派生快照 | 由 `Editor` 拥有 |
| 当前帧布局、shaped line、像素命中结果、绘制缓存 | `EditorElement` | 当前帧临时数据 | 每次布局重新生成，不长期保存 |
| 文件到文档实体的索引 | `Project::BufferStore` | 弱引用；按路径复用 | 最后一个使用者释放后整条文档链结束 |
| Git 修订文本 | `Project::GitStore` | 按 `(revision, path)` 唯一的 `Entity<LanguageBuffer>` | Git 状态刷新时创建与替换 |

### 3.2 权威状态与派生状态

- 一事实只有一个可写所有者。其他层持有的同义数据只能是：不可变快照、从权威派生且可丢弃的缓存、或指向权威的 `Anchor`。
- 派生数据失效后必须从权威重新派生，不允许反向修补权威。
- 授权删除、重算或重建派生缓存的控制流，必须经过该派生数据的唯一推进入口。

### 3.3 典型影子副本（禁止）

- 在 `Editor` 或 `EditorElement` 中保存可编辑的文本内容；
- 在 `Editor` 中保存第二份 excerpt 列表或组合坐标权威；
- 在 `Editor` 中保存第二份可写的显示行表，或与 `DisplaySnapshot` 并列维护显示坐标权威；
- 在 UI 中保存文档内容、选择或滚动状态的可写副本；
- 在 `MultiBuffer` 中保存源文档可独立修改的文本副本；
- 同一事实同时由订阅回调和显式刷新两条路径推进。

## 4. 坐标空间、位置与版本语义

### 4.1 坐标空间

编辑器核心至少存在五个坐标空间，必须有明确的 newtype 与转换边界：

~~~text
源坐标            ByteOffset / CharOffset / Position / Utf16Offset
    │  zcv-text::Snapshot
    ▼
组合源偏移        ExcerptOffset（各 excerpt 可见内容拼接，不含展开的删除段）
    │  diff transforms
    ▼
组合输出坐标      MultiBufferOffset / MultiBufferPoint / MultiBufferRow / MultiBufferAnchor
    │  zcv-multi-buffer::MultiBufferSnapshot
    ▼
投影坐标          FoldOffset/FoldPoint → TabPoint → WrapRow/WrapPoint
                  → BlockPoint/DisplayPoint/DisplayRow
    │  zcv-editor::DisplaySnapshot
    ▼
像素坐标          gpui Point<Pixels>
~~~

组合源偏移与组合输出坐标必须区分：前者不含展开的删除段，后者包含。从源坐标到输出坐标的转换必须先经删除段投影，再经 excerpt 映射，不允许直接线性映射。每次转换都必须显式写出源坐标与目标坐标；不同层不得复用一个含义不同的裸 `usize`。

### 4.2 位置语义

- 长期状态保存 `Anchor`，不保存依赖旧快照的裸 offset、行列或显示点。
- `Anchor` 是不可变值，自身不推进；它绑定创建时的内容代际、版本与吸附方向，解析时在目标快照上重新定位。可用的推进方式是「随编辑增量一起映射到新版本」或「在目标快照上重新解析」；不得把锚点原始偏移直接当作目标快照坐标。
- 长期锚点由 Buffer 的不衰减坐标索引解析：索引只保存 old range 与 replacement 长度等坐标增量，不复制替换文本，也不随 `max_edit_history_entries` / `max_edit_history_bytes` 裁剪。带文本编辑日志的预算收敛只影响 `edits_since` 增量同步与 undo/redo 窗口，不影响长期锚点。
- reset / 基线替换开启新的内容代际；旧代际锚点在普通解析中显式失败，不会被当作普通版本推进继续映射，也不会被静默钳到邻近坐标。需要跨重置恢复调用方稳定表示时，必须走显式重锚（例如外部 reload 后按 reset 的坐标映射恢复光标），不能把该路径隐藏在普通解析里。解析失败（代际被替换、目标版本更旧、端点退出投影）时，调用方必须显式处理（丢弃、重锚或回退到自己的稳定表示），不得猜测坐标。
- `Affinity` 是 `Anchor` 语义的一部分，决定插入发生在边界时锚点吸附到插入内容之前还是之后。折叠、diff hunk 等「只跟随原有文本」的范围用 inside 语义；自动闭合区域等「吸收边界插入」的范围用 outside 语义。
- `Bias`／`Stickiness` 只在 seek 与位置映射的明确边界使用，不替代 `Affinity`。
- UTF-16 坐标只用于输入法、系统文本接口等外部边界；内部不以 UTF-16 作为主坐标。

### 4.3 版本与快照

- 每份文本都有一个单调推进的源版本。快照、Anchor、Edit 都必须能回答「属于哪个版本」。
- 一个 `Snapshot` 是不可变、可廉价克隆的读取边界，携带生成它时的版本与足以跨版本解析锚点的编辑日志。
- 组合文档、显示投影各自也有版本；上一层的快照必须固化下一层同版本的快照，使一次读取看到内部一致的一条链。
- 语法快照必须与文本版本绑定；任何重解析结果只有在其解析基准版本与当前文本版本一致时才允许安装。

## 5. zcv-text：文本事实内核

### 5.1 职责

`Buffer` 是源文本的唯一可写所有者，拥有：

- 文本存储；
- 当前版本与保存点版本；
- 事务提交管线；
- 版本化的编辑日志；
- 撤销／重做历史。

`Snapshot` 是不可变读取视图：文本读取、坐标转换、Anchor 解析、自旧版本以来的净编辑。

### 5.2 事务模型

一次文本修改必须经过事务：

~~~text
Transaction { base_version, edits, metadata }
    → 校验 base_version 与当前版本
    → 归一化为有序、不重叠的 EditList
    → 原子应用到存储
    → 追加版本化编辑日志
    → 产生 DeltaEvent / TextChangeBatch
    → 收尾 history（是否形成历史节点、undo 逆编辑）
~~~

要求：

- 版本失配是错误，必须显式失败，不得静默重算或在旧版本上强行应用。
- 事务要么完整生效，要么不产生任何状态推进。
- 编辑是否进入历史、如何合并，由本次事务的 metadata 决定；空会话不产生历史节点，也不发布编辑事件。
- `Buffer::edit` 之外不得存在第二条直接修改文本的路径。

### 5.3 历史、版本与编辑日志

- 版本是「某个时刻文本可见状态」的因果标识，必须支持：从某版本到当前版本的净编辑查询、在某个历史版本上判断某段文本是否可见、把当前坐标映射回旧版本。这些能力服务增量同步、语法增量、diff 与 Git 修订对比，**不是协作专属**；核心是版本抽象本身，协作只是把它扩展成多副本向量。Zcv 保留版本抽象，只去掉多副本维度。
- 版本化编辑日志是「从某版本到当前版本的净编辑」的唯一事实，供 `edits_since` 增量同步与 undo/redo 回放使用；长期锚点跨版本定位由独立的不衰减坐标索引承担，二者在同一次提交追加。
- 不衰减坐标索引与编辑日志职责分离：坐标索引只保存映射坐标所需的信息且永不裁剪；编辑日志保存带文本的编辑事实并受预算裁剪。reset 开启新代际，普通解析拒绝把旧代际锚点当作普通版本推进；跨代际映射仍保留在索引中，只有调用方显式重锚（`rebase_across_generations`）才会使用。
- 历史只保留分支拓扑、事务身份与版本区间；undo／redo 的可重放编辑从编辑日志的版本区间读取，不重复保存第二份编辑事实。
- 撤销需要「某次插入在某历史版本上是否可见」的判定，因此编辑日志必须与撤销状态一起支持历史可见性查询，而不只是当前文本差异。
- 撤销／重做同样走正常的事务结果与订阅路径，并返回被回放节点的事务身份，供编辑器恢复选择。
- 保存点只保留 `saved_version`；dirty 由「自保存点以来是否存在结构性编辑」派生，不保存第二份文本指纹。

### 5.4 订阅与增量

- 订阅采用「每消费者独立批次」模型：宿主事件只负责唤醒消费者，消费者读取当前 `Snapshot` 并消费属于自己的 `TextChangeBatch`。
- 批次携带旧／新坐标空间的范围与 `PositionMap`，供上层把坐标推进到新版本。
- 订阅提供的是「自消费者上次消费以来的累积变化」；而「从任意旧版本到现在」的查询由快照的 `edits_since` 完成。两条通道互补：订阅驱动实时缓存平移，版本查询支持任意跨度的重算与历史对比。
- 不存在全局待消费队列，不同订阅者互不争抢，也不依赖自己消费的时机。
- 后台派生文档模式：需要在一个稳定基线上计算（例如 Git 修订文本、diff 基线）时，在快照副本上应用编辑得到一个派生快照，再在主文档版本未变的前提下原子替换。该模式与订阅、历史解耦，但必须做版本校验。

### 5.5 明确不属于本层

`zcv-text` 不负责：UI 渲染、文件读写与编码、语法树、项目索引、搜索、LSP、协作与远程。

### 5.6 不变量

- T-1：`Buffer` 是文本内容、版本与历史的唯一可写所有者。
- T-2：任何文本修改都必须经过带版本校验的事务。
- T-3：`Anchor` 是不可变值，自身不推进；解析时在目标快照上重新定位。禁止把锚点原始偏移直接当作目标快照坐标，也禁止跨版本直接复用偏移。长期锚点解析只依赖不衰减坐标索引，不依赖被预算裁剪的带文本编辑日志。
- T-4：`Snapshot` 一旦创建即不可变，且其内容与版本一致。
- T-5：编辑日志是净编辑的唯一事实；历史不复制编辑列表。
- T-6：不存在无订阅、无历史的旁路写入。
- T-7：版本抽象必须支持历史可见性、任意跨度净编辑与历史文本重建；多副本维度被裁剪，但这些查询契约保留。
- T-8：锚点解析必须绑定目标快照；代际被 reset / 基线替换、目标更旧或端点退出投影时解析失败必须显式暴露（Result 或明确命名的失败），调用方丢弃或重锚，不得猜测坐标。
- T-9：后台派生快照只能在版本校验通过后原子替换，且不得绕过订阅与历史。

## 6. zcv-language：文本与语法的一致快照

### 6.1 职责

`LanguageBuffer` 是「一个打开文档」的语言能力边界，拥有：

- 直接持有的文本 `Buffer` 与其语法解析状态；
- 语法树与多语言注入层；
- 后台解析任务与取消；
- 按 buffer／language 解析后的语言设置缓存；
- 有界高亮缓存。

它对外暴露一致读取边界 `LanguageBufferSnapshot`：文本快照与语法快照保证同一版本，并同时携带语言、语言设置、文件身份与高亮缓存句柄。另有一个同源只读文本快照访问器（`text_snapshot`），它直接取自同一份权威文本，不构成第二数据源；需要文本与语法同版本的消费方必须走一致快照。

### 6.2 语法的所有权分工

- 文本权威是 `LanguageBuffer` 直接持有的 `Buffer`；语法权威是同实体的语法映射；**查询权威在 `Language`／`Grammar`**，而不是 `Buffer`。
- 所有 Tree-sitter 查询在语言装配时编译进 `Grammar` 的查询配置；运行时对象只持有 `Language`／`Grammar`，不重新持有 `.scm` 源文本。
- 查询的「种类」与「遍历机制」分离：调用方按查询种类选择 `Grammar` 上的查询配置，遍历本身在语法快照上完成。
- `Grammar` 构造后基本不可变；运行时可变的只有主题相关的高亮映射，由应用／注册表拥有并在主题变化时广播，不能让每个 `LanguageBuffer` 各存一份。

### 6.3 语法快照与增量解析

- 语法快照区分「已插值版本」与「已解析版本」：前者表示文本编辑已以 `InputEdit` 打到树上，后者表示真正完成了解析。两者语义不同，不可混用；混用会丢失增量编辑。
- 每个文档同时只允许一个后台解析任务；重解析请求在已有任务时合并，不并发解析同一文档。
- 编辑后先插值使树位置跟随文本；后台增量解析完成后再安装真实结果。安装前必须校验解析基准版本与当前文本版本一致；过期结果丢弃并重新调度。
- 语法层的范围用 `Anchor` 保存，随文本编辑自愈；查询时才解析为字节范围。这是「语法树不因编辑而整体失效」的关键。
- 注入语言：注入查询产生多层语法树；尚未加载的注入语言以「待解析层」保留，并在语言注册表版本变化后补解析，不能静默丢弃。
- 解析完成属于非文本状态更新，必须递增独立于文本版本的元数据版本并通知上层；只比较文本版本会丢失语法更新。

### 6.4 查询边界

语法能力以 Tree-sitter 查询（`.scm`）为边界，至少包括：高亮、括号、缩进、折叠候选、大纲、语法节点、局部绑定、结构化选择扩展。新增语法感知能力优先扩展查询与语言层结果类型，不预建 LSP 兼容接口。

### 6.5 语言设置

- 语言设置的**政策所有者是设置存储**；`LanguageBuffer` 只持有按 buffer／language 解析后的缓存，在设置变化时重算，不反向写回设置，也不在上层复制第二份。
- tab 宽度、硬/软 tab、软换行、preferred line length 等按语言解析；编辑器与显示投影读取快照上的设置，而不是全局设置单例。
- 词边界属于语言配置数据（语言拥有的字符分类），不是设置项；文本层移动 API 显式接收它。

### 6.6 生命周期

- `LanguageBuffer` 直接持有文本 `Buffer`，二者同生命周期；销毁时取消后台解析任务。
- 语言注册表由应用装配层显式创建并注入；注册表版本变化驱动注入层补解析。语言层不提供隐式全局单例。

### 6.7 明确不属于本层

- LSP 客户端、语言服务器 Store、服务器诊断、服务端 semantic token、代码操作、hover、服务器生命周期；
- 编辑器交互状态（选择、滚动、输入法）；
- 文件读写与项目索引。

### 6.8 不变量

- L-1：`LanguageBufferSnapshot` 中文本与语法必须是同一版本。
- L-2：「已插值版本」与「已解析版本」语义分离，过期解析结果绝不安装到新版本。
- L-3：同一文档同时只有一个后台解析任务。
- L-4：语法查询只消费匹配版本的快照，结果携带版本。
- L-5：高亮缓存有界、可丢弃，随文本版本或解析安装整体失效。
- L-6：语言设置按 buffer／language 解析并在快照中下发，不在上层复制。
- L-7：解析等非文本状态变化有独立的元数据版本，必须推进上层快照链。
- L-8：尚未加载的注入语言保留为待解析层，不静默丢弃。

## 7. zcv-multi-buffer：组合文档与 diff 投影

### 7.1 职责

`MultiBuffer` 是「编辑器消费的文档内容」的权威组织者，拥有：

- excerpt 的有序集合；
- excerpt 到源 `LanguageBuffer` 的映射；
- 三个坐标空间的映射（源偏移、未删除拼接偏移、含删除 hunk 的输出偏移）；
- diff 投影（虚拟内容与 hunk 身份）；
- 组合层的事务与历史；
- 对源文档变化的订阅与组合层事件。

它不拥有源文本；源文本仍由各 `LanguageBuffer`／`Buffer` 拥有。它也不是编辑器：不持有选择、滚动、折叠、语法高亮或渲染状态。

### 7.2 excerpt 布局与坐标空间

组合文档必须显式区分三个偏移空间和一个行列空间：

~~~text
源偏移        BufferOffset           底层文档可见文本内偏移
    │  excerpts
    ▼
未删除拼接偏移 ExcerptOffset         各 excerpt 可见内容拼接后的偏移（不含展开的删除段）
    │  diff transforms
    ▼
输出偏移      MultiBufferOffset      最终组合文档偏移（含展开的删除段）
              MultiBufferPoint / MultiBufferRow   输出空间的行列
~~~

- 每个 excerpt 至少携带：源文档身份、源 `Anchor` 范围（区分 context 与 primary）、显示路径及其索引、预计算文本 summary、尾部换行标志。
- `PathKey` 是 excerpt 的排序键，`PathKeyIndex` 是它在路径索引中的紧凑序号；`MultiBufferAnchor` 只携带序号而不是完整路径。
- 组合锚点至少区分：全局最小／最大、以及「excerpt 身份 + 源 Anchor」。源 Anchor 是唯一长期位置，路径序号只用于当前快照内定位。
- excerpt 结构由 `SumTree` 承载；组合坐标查询通过 summary/dimension 与 cursor 连续推进，而不是构造扁平数组后二分。
- 普通编辑器是「整文件单 excerpt」的组合文档；多文件差异与搜索结果是多 excerpt 组合文档。单 excerpt 是同一模型的快路径，不是第二种文档类型。

### 7.3 diff 投影

- 唯一 diff 事实来自独立的 diff 能力域；`MultiBuffer` 通过显式注入把 diff 叠加为投影，而不是把 diff 视图做成另一种文档类型。
- 投影用一棵变换树表达：内容变换保持输入等于输出；删除 hunk 的输入为空、输出是被删文本。删除 hunk 的文本来自 diff 基线，而不是当前文档。
- hunk 身份随投影变换节点承载，不在投影之外维护第二份源坐标副本；hunk 到输出坐标的定位通过 cursor 遍历。
- 旧侧只读 excerpt 只参与选择、复制与导航，不接受组合编辑；编辑落点必须跳过删除 hunk 或重定向到内容节点。
- 结构重建（excerpt 顺序变化、diff 展开／折叠、外部源变更）后，组合坐标与显示坐标必须由源 `Anchor` 重新解析；不得把重建前的偏移直接当作重建后的偏移。

### 7.4 事务与历史

- 组合编辑先映射为源 `Buffer` 的编辑，再按源事务提交；组合层不维护第二份可写文本。
- 单源组合文档的历史可以由源文档历史承担；多源组合文档拥有自己的组合历史，它只保存「组合事务身份 → 各源事务身份」的映射，实际可重放内容仍在各源文档历史中。两条路径共享同一套「事务身份 + 源 Anchor 选区」语义。
- 组合事务结束时若没有任何源事务成立，则该组合事务必须被丢弃，不留下空历史节点。
- excerpt 增删、diff 展开折叠等结构性变更必须在文本事务之外进行，不允许嵌套在编辑会话里。
- 组合层向外发布变化事件，上层据此推进显示投影与选择。

### 7.5 订阅与同步

组合文档有两条职责不同、不可混用的通道：

- 文本内容：源文档只置「已变化」脏位；`MultiBuffer` 在读取时按源版本自上次已同步版本拉取净编辑。不得为每次源编辑立即全量重建快照。
- 语义事件：源文档的语言状态、设置、保存、重载、能力变化等以语义事件转发，并推进组合层的非文本版本。

要求：

- 语言状态、设置、注入等纯元数据变化与文本变化都必须推进组合快照与显示链；只比较文本版本会丢失新快照。diff 显示几何使用独立的不可变显示输入与显示版本，只替换装饰，不混入语言／设置元数据版本或显示拓扑同步。
- 组合层向外同时发布粗粒度语义事件与细粒度输出偏移增量：前者驱动语义刷新，后者让选择与显示层增量平移缓存。
- 源文档打开／关闭／重载／保存的生命周期由文档索引与工作区协调；源文档消失时相应 excerpt 与历史必须明确失效。

### 7.6 明确不属于本层

- 语法解析与 Tree-sitter 查询（属于语言层）；
- 选择、滚动、输入等交互状态（属于 `Editor`）；
- 显示行、软换行与像素布局（属于显示投影与渲染层）；
- LSP、协作、远程能力。

### 7.7 不变量

- M-1：`MultiBuffer` 不持有源文本的第二份可写副本。
- M-2：excerpt 顺序与 diff 投影在组合层只有一个权威结构；投影变换树的「未删除输入」必须与 excerpt 树的文本 summary 一致。
- M-3：组合坐标查询通过连续 cursor 推进，不依赖扁平化 excerpt 数组。
- M-4：结构重建后位置由源 `Anchor` 重新解析。
- M-5：文本与元数据变化都推进快照链；不能只依赖文本版本判定是否需要同步。
- M-6：源编辑与组合编辑走同一条源事务路径。
- M-7：excerpt 按路径键升序、同路径内不重叠；除最后一个 excerpt 外都必须带尾部换行，最后一个必须不带。
- M-8：组合事务只保存源事务身份映射；结构变更在文本事务之外。
- M-9：编辑落点只允许落在可写且非删除段的内容上。

## 8. zcv-editor::DisplayMap：显示投影链

### 8.1 层次与顺序

显示投影由固定的自底向上层链构成：

~~~text
MultiBufferSnapshot
    → FoldMap    折叠范围与折叠后的文本拓扑
    → TabMap     硬 Tab 的显示列
    → WrapMap    按像素宽度软换行（异步重排）
    → BlockMap   文件标题、分隔线等虚拟块，负责合成换行
    → DisplaySnapshot
~~~

层顺序是架构的一部分：每层只处理自己负责的变换，并把结果与增量交给上一层。改变顺序会改变所有上层坐标语义，必须有明确证据。

只有软换行层是需要独立通知的异步实体；其余层是同步投影，不各自对外发事件。异步链路的通知方向固定为：软换行层 → 显示投影 → 编辑器。

### 8.2 每层的统一协议

每个投影层都必须提供以下等价能力：

- `Transform`：该层管理的文本区域。至少区分「同构（透明传递）」与「该层施加变换」两类。
- `TransformSummary`：至少包含 `input` 与 `output` 两个文本 summary，使上层能同时定位下层坐标与本层坐标。
- 本层坐标 newtype：与输入、输出坐标显式区分，避免裸偏移混用。
- `Snapshot`：某一时刻的不可变本层状态，并固化下层同版本快照。
- 同步入口：`sync(下层快照, 下层 edits) → (本层快照, 本层 edits)`。
- 正向／反向坐标转换；
- 行与 chunk 的 cursor／iterator，供渲染按需读取。
- 面向单行 shaping 的文本行 chunk 只携带行内容，不携带 `\r`／`\n` 终止符；终止符仍属于下层文本快照的坐标与行数事实。不得把去除终止符的责任分散给各个渲染调用点。

允许的两种入口形态：

- 返回「新快照 + 本层 edits」的同步形态；
- 读／写分离形态：读入口只取快照，写入口持有可变的层状态。折叠这类需要写句柄持有生命周期的层使用后者。两种形态共享同一套坐标与 Edit 语义，不得为了形式统一而破坏写句柄生命周期。

硬 Tab 层是一个刻意的例外：它不建立持久的变换树，而在读取上层 chunk 时按列位置即时计算展开结果，以便正确理解同一行内后续 Tab 与显示列的关系。这个例外必须保留，不要为了「每层都有投影树」而强行套用同一形态。

关键语义：`Edit` 表达的是「需要失效的区域」，而不是「发生了什么变化」。它可以被安全地放大为覆盖更大范围，代价是多余重算。上层只根据旧／新区域重新定位，不得假设 `Edit` 给出了精确差量。

### 8.3 坐标与快照

- 逐层坐标必须用独立类型区分：fold、tab、wrap、block/display。
- `DisplaySnapshot` 是最上层快照，内部按链嵌套下层快照；任意一份 `DisplaySnapshot` 都对应唯一一条内部一致的版本链。上层可以只读穿透到下层，但写方向仍严格由 edit 逐层向上传递。
- 渲染与命中测试只读取 `DisplaySnapshot`，不自行向更下层查询。
- 显示点由「显示行 + 显示列」表达；wrap 行与显示行必须区分，虚拟块插入后由 block 层完成 wrap→display 的转换。
- 边界归属（Bias）语义必须显式传入每一次跨层转换；折叠、虚拟块边界上的光标与选择都依赖它。

### 8.4 增量同步

- 显示链的唯一推进入口是 `DisplayMap` 的同步：从组合快照消费下层 edits，逐层转换，产生新的 `DisplaySnapshot`。
- 源编辑先进入订阅队列，由显示投影在读取或执行显示命令时消费；不在每次源编辑时立即重算整链。
- 每层必须正确消费下层 edit 并输出自己的 edit；不允许某层跳过上层协议、直接读取更下层的原始批次。
- 投影拓扑重建（折叠、软换行结构变化）也必须走同一同步入口；重建后由源 `Anchor` 重新解析选择、滚动与装饰范围。
- 同步的快速路径必须纳入所有会影响显示拓扑的输入：文本版本、元数据版本、捕获表／高亮配置等。diff 显示输入不改变拓扑，应由装饰层按其独立版本替换；只比较文本版本会在纯元数据变化时漏同步。
- 软换行层异步重排：结构编辑先以同构方式急切替换、保持可用快照；后台重排期间用插值编辑累积，真实结果落地时以组合 Patch 先反转插值再叠加真实编辑，并只对上层发布净编辑。
- 软换行层的中间态必须自洽：只要当前快照是插值态，就必须存在后台任务或明确的「无需换行」配置；否则会出现永不收敛的重排状态。

### 8.5 元数据与装饰

- 语法高亮、诊断、搜索命中、diff 装饰等是基于快照的元数据消费方，不复制文本或坐标权威。
- 显示投影持有「文本高亮区间」这类显示元数据的权威（以 `Anchor` 区间表达）；语法高亮与诊断严重度随 chunk 流经各层，不参与坐标转换。
- 搜索命中、diff hunk、宿主注入 hunk 与折叠候选（crease）统一表达为「领域键 + 组合锚点范围」的显示装饰输入，由显示投影在同一显示版本上投影为显示坐标；权威仍是各自的领域所有者，显示投影只拥有该版本上的只读投影。
- `CreaseMap` 只保存宿主显式注入的组合锚点范围，并以稳定身份移除；语法折叠不在 `MultiBuffer` 或 `CreaseMap` 中物化整份源文件列表。`DisplaySnapshot` 按当前可见逻辑行取得源快照、执行 Tree-sitter 查询，再通过组合层的坐标映射投影候选；光标位于折叠体内部时可以按需查询所在单一源，但不得形成跨源缓存或同步路径。
- 显示装饰随 `DisplaySnapshot` 整体替换、可丢弃、可重建；渲染只从 `DisplaySnapshot` 按视口查询，不在 `Editor` 中保存并列的显示坐标装饰副本。diff 装饰输入由 `MultiBufferSnapshot` 固化，几何未变时复用已投影的装饰快照。
- 元数据必须以「随快照失效、可重建」的方式接入，不能跨版本缓存后在当前文本上解释旧坐标。语言、设置和捕获表等影响显示拓扑的非文本变化推进组合元数据版本；diff 几何变化推进其独立显示版本，避免显示链的快速路径被无关装饰刷新放大。
- 渲染接缝（折叠占位符绘制、虚拟块绘制）是投影层对外的唯一 UI 耦合点；投影的数据结构本身不应依赖具体渲染，除非明确把它作为唯一接缝维护。

### 8.6 明确不属于本层

- 文本内容、excerpt 顺序与 diff 投影（属于下层）；
- 选择、滚动、输入等交互状态（属于 `Editor`）；
- 逐帧行布局、shaping 与像素命中（属于 `EditorElement`）。

### 8.7 不变量

- D-1：层顺序固定；每层只依赖其下层。
- D-2：每层同时提供快照、正反坐标转换、cursor 与增量 edit 映射。
- D-3：`Edit` 表示待失效区域，不承诺精确差量。
- D-4：`DisplaySnapshot` 内部嵌套下层同版本快照，构成唯一一致链。
- D-5：同步只有一个入口，快速路径覆盖全部影响结果的状态。
- D-6：结构重建后由源 `Anchor` 重新解析位置。
- D-7：显示热路径不物化整行或整份文本，只按可见范围与 cursor 读取；面向单行 shaping 的文本 chunk 只输出无行终止符的行内容。
- D-8：每层变换树的 input 必须精确覆盖下层内容；同构段不得被合并，以保证编辑边界与变换边界对齐。
- D-9：折叠有序、不重叠；折叠身份单调唯一，范围用 `Anchor`。
- D-10：虚拟块层重建后，输入行数必须与软换行层的行数一致；块行合成的换行必须让显示行数与投影一致。
- D-11：跨层转换必须显式给出 Bias。
- D-12：只有软换行层是异步实体；其插值态与后台任务必须同时成立。

## 9. zcv-editor::Editor：交互状态与事务编排

### 9.1 职责

`Editor` 是交互状态的所有者与编辑事务的编排者，不是第二个文档模型。它拥有：

- 当前组合文档实体与显示映射实体的句柄；
- 选择集合、选择历史、结构化选择链；
- 滚动位置与滚动几何；
- 输入法组合会话；
- 搜索状态与折叠开关；
- 鼠标手势（拖拽选择、粒度、自动滚动限频）；
- 局部重命名会话、自动闭合区域等编辑辅助状态；
- 焦点、光标闪烁与显示配置；
- 领域事件。

它消费文档与显示快照，并把用户操作转化为文本事务、显示配置变化或事件。

### 9.2 持有关系与派生快照

- `Editor` 持有组合文档实体与显示映射实体；显示映射持有同一个组合文档实体。二者是同一个文档的两个同级消费者，不是父子关系。
- `Editor` 不拥有可独立修改的文本、excerpt 或显示行权威。需要文档／显示事实时，从显示映射按当前版本链派生的显示快照读取。
- 搜索命中、diff 装饰、宿主注入 hunk 与折叠候选属于显示装饰：`Editor` 只把领域锚点范围注入显示投影，显示坐标投影与视口查询由 `DisplaySnapshot` 提供；`Editor` 不保存显示坐标装饰缓存。
- 显示快照的规范来源是显示映射：由显示映射的唯一同步入口消费下层增量、逐层推进并产生当前快照。默认在需要时派生，而不是由多个订阅者分头写入。
- 如果因为借用或生命周期原因保留了派生显示快照缓存，它必须是唯一的一份，由同一个同步入口整体替换；不得同时存在「显示映射内的快照」与「编辑器内的快照」两级同源缓存。
- 可以为当前帧聚合一个渲染快照，至少包含显示快照、滚动锚点、显示配置与焦点；**选择不在其中**，选择集合是 `Editor` 的活权威状态，由渲染层按当前快照解析。
- 派生快照是整体替换的：任何操作不得局部修改它，也不得在同一命令内混用新旧快照。
- 允许直接读取权威 `MultiBufferSnapshot` 的唯一场景是公开只读边界与活性校验（例如确认两次读取之间没有外部编辑）；这不构成第二条同步路径。

### 9.3 选择模型

- 单个选择采用「有序端点 + 方向 + 垂直移动目标」模型；集合负责排序、合并与 primary 归属。
- 持久态选择保存 `MultiBufferAnchor`，消费时按当前快照解析为偏移；算法态可以使用偏移。
- 选择集合由两部分构成：已确定且互不重叠的选择，以及一个进行中的手势选择；外部读取时按合并规则合并。
- 锚定选择的吸附规则必须固定：caret 吸附到插入文本之后；非空选区的起点吸附到插入之前、终点吸附到插入之后，使边界插入不撑大选区。
- 选择合并只在真正重叠、包含或光标贴边时发生；仅仅相邻不合并。
- 所有选择变更必须经唯一的选择变更入口，以保证排序、合并与不变量。嵌套变更在延迟效果区间内累积，最外层结束时一次性应用，避免中间态进入历史。
- 选择历史与文本事务通过 `TransactionId` 关联：成功的事务记录编辑前／后选择，undo／redo 同时恢复文本与选择。
- 结构化选择扩展链在普通选择变化或文本编辑后失效，并统一收敛到选区变更入口。
- 鼠标手势中的锚点与粒度属于 `Editor`；手势结束后落为普通持久选择。

### 9.4 事务与历史分工

- 文本历史（可重放的编辑）由文本层拥有；选择历史由 `Editor` 拥有；两者只通过 `TransactionId` 关联，互不复制对方的权威数据。
- 所有文本修改统一经 `Editor` 的编辑入口提交：开启事务 → 记录编辑前选择 → 构建组合编辑计划 → 提交到 `MultiBuffer` → 推进显示快照 → 解析选择落位 → 记录编辑后选择并结束事务。
- 编辑前快照是本次事务的局部输入，不进入 `Editor` 长期状态。
- 顺序不可颠倒：先提交文本，再推进显示投影，最后落地选择。选择落位依赖新快照。
- 编辑失败必须结束空事务、恢复编辑前选择，并向用户可见地报告，不能残留会阻塞后续编辑的会话。
- 输入法组合、搜索替换、局部重命名、自动闭合、结构化编辑都必须进入同一条事务路径，不允许在 `Editor` 内直接维护文本副本。
- undo／redo 由文本历史回放驱动；文本层返回被回放的事务身份，`Editor` 据此从选择历史恢复选择，并复用同一事务结果路径推进显示与事件。

### 9.5 输入与组合输入

- 输入处理的唯一入口负责把一次输入转换为「编辑集合 + 新选择」，再由事务路径统一提交；自动闭合、auto surround、代码片段等本地编辑能力都在这里产生编辑，不各自写文本。
- 输入法组合通过系统输入接口进入同一事务路径；组合期间用事务分组把一次组合的多个事务合并，并在显示投影上叠加组合区域的显示标记。
- 组合输入期间必须关闭会与组合语义冲突的自动编辑（自动闭合、auto surround），组合结束时清除标记与分组身份。

### 9.6 滚动

- 长期滚动位置保存为「组合 `Anchor` + 锚点行内像素余量」，不长期保存显示点。
- 显示行与像素位置在布局时按当前 `DisplaySnapshot` 解析。
- 待执行的自动滚动同样保存 `Anchor`；只有需要像素几何的水平钳制才依赖布局结果。
- 滚动锚点必须由 `Editor` 拥有；分栏对齐等场景可以共享锚点身份，但不得让渲染层成为滚动权威。

### 9.7 事件

- `EditorEvent` 表达编辑器领域事实：文件路径变化、真实事务编辑、dirty 变化、复合文档打开请求、diff 展开状态变化、错误等。
- 编辑事件只在真实事务提交时发布，并携带 `TransactionId`；空事务、no-op 编辑、undo／redo 复用同一出口，不各自发明事件。
- 事件只表达通知语义；跨 crate 的类型擦除边界可以翻译事件，但不能建立第二套事件协议。

### 9.8 只读与能力

- 可编辑性由文档能力与 `Editor` 的只读策略共同决定；只读编辑器仍复用同一套选择、滚动、定位与渲染管线，只禁用文本修改。
- 只读不意味着维护一套平行的只读编辑器。

### 9.9 明确不属于本层

- 文本内容、版本与历史（属于文本层）；
- 语法状态与解析（属于语言层）；
- excerpt 顺序与 diff 投影（属于组合文档层）；
- 显示行拓扑、软换行与虚拟块（属于显示投影层）；
- 逐帧布局、shaping 与像素命中（属于 `EditorElement`）；
- 文件读写、Git 修订文档、工作区标签（属于 `Project`／`Workspace`）；
- 宿主工具区视图与工具项注册（属于 `Workspace`／`Pane` 装配层）。

### 9.10 不变量

- E-1：`Editor` 不拥有第二份可写文本、excerpt 或显示行权威。
- E-2：派生快照只经唯一推进入口整体替换；选择不在派生快照中，选择权威始终是选择集合。
- E-3：所有文本修改都进入统一事务路径。
- E-4：长期位置状态保存 `Anchor`，消费时按当前快照解析。
- E-5：文本历史在文本层、选择历史在 `Editor`，两者通过 `TransactionId` 关联。
- E-6：编辑事件只在真实事务提交时发布。
- E-7：所有文档形态共用同一个 `Editor` 管线。
- E-8：所有选择变更经唯一入口；锚定吸附规则与合并规则固定。
- E-9：事务结果落地顺序固定为「文本 → 显示 → 选择」。

## 10. EditorElement：逐帧布局、绘制与命中

### 10.1 职责

`EditorElement` 是渲染层，负责当前帧：

- 从 `Editor`／`DisplaySnapshot` 读取可见行与显示点；
- 对可见文本做 shaping 与行布局；
- 计算 gutter、装饰、光标、滚动条等像素几何；
- 命中测试：把像素位置映射回显示坐标；
- 处理布局阶段的滚动与输入布局回写。

### 10.2 边界

- `EditorElement` 只拥有当前帧临时数据。它可以缓存与版本绑定的像素结果，但这些缓存必须随版本失效，且不得写回文档事实。
- 允许把上一帧的几何结果（边界、gutter 尺寸、可见行范围、布局）写回 `Editor` 的缓存字段，供布局外的命中测试复用。这属于缓存语义，不是权威状态；权威仍是当前快照与 `Editor` 的交互状态。
- 渲染不得触发文本修改；需要修改文本的操作必须回到 `Editor` 的事务入口。
- 渲染不得重新物化整份文本或整份投影文本；只按可见范围与 cursor 读取。

### 10.3 不变量

- R-1：`EditorElement` 不写回文档、选择或显示权威状态。
- R-2：布局只读取当前版本链一致的快照。
- R-3：像素缓存随版本失效，可丢弃、可重建。
- R-4：热路径不物化整份或整行投影文本。

## 11. 工程边界：Project、Item 与 Workspace

### 11.1 文档与文件

- `Project` 的文件边界负责：按路径打开文件、解码、创建 `Buffer`、建立 `LanguageBuffer`，并按路径复用仍存活的文档实体。
- 文件到文档的索引保存弱引用：只要还有 `Editor` 或视图持有文档，就复用同一条文档链；最后一个使用者释放后整条链结束。
- 同一路径只有一个权威文档实体；不得为同一文件在保存、diff、搜索等入口各自物化第二份可写文档。
- Git 修订文本（例如 HEAD／index）由 `GitStore` 按 `(revision, path)` 唯一持有，版本控制视图与 diff 不再各自物化。

### 11.2 Item 与 Workspace

- 每个 `Editor` 通过 `Item` 协议进入工作区；工作区只拥有窗口级容器、标签生命周期、Dock、持久化和命令分发，不复制编辑器或文档状态。
- `Pane` 拥有自己的工具区（`Toolbar`）；`Item` 只通过 `show_toolbar` 与面包屑数据参与工具区，不持有也不返回工具区视图。工具项实现 `ToolbarItemView`，由装配层注册到 Pane 的工具区，并依据活动 `Item` 决定位置与显隐。
- 工作区不直接拥有文本、语法、组合文档或显示投影；它通过实体关系持有 `Item`，并把命令路由到真正的状态所有者。
- 预览、搜索等派生视图消费同一条文档与显示管线，不建立平行编辑流程。
- 项目级搜索继续通过现有 `SearchableItem`／`SearchableItemHandle` 进入搜索栏和结果编辑器；搜索结果仍复用 `MultiBuffer` 与唯一 `Editor` 管线，不为项目查询建立专用 handle。

### 11.3 不变量

- P-1：同一路径／修订只有一个权威文档实体。
- P-2：Project 的文件边界不把文本、语法或组合文档的可写权威上移为产品层状态。
- P-3：Workspace 不复制 Item 的领域状态。
- P-4：Project 的文件边界不依赖组合文档；打开、保存、重载面向文档实体与文本快照。

## 12. 编辑与状态变化的传播路径

### 12.1 键盘／程序化编辑

~~~text
Action / 输入
  → Editor 按当前快照解析持久选择（Anchor → offset）
  → Editor 开启事务，构建组合编辑计划
  → MultiBuffer 把组合编辑映射为各源 Buffer 的编辑
  → Buffer 校验版本、原子应用、追加编辑日志、发布批次
  → MultiBuffer 自源版本拉取净编辑，重建组合快照与投影
  → DisplayMap 逐层同步：Fold → Tab → Wrap → Block
  → Editor 推进唯一派生快照，按新快照解析选择落位
  → Editor 结束事务；真实事务才记录 redo 选择并发布 Edited{TransactionId}
  → EditorElement 在下一次渲染读取新快照布局与绘制
~~~

要点：编辑落位不以旧显示坐标为准；选择是源锚点，投影重建后自动跟随。

### 12.2 外部源编辑（另一编辑器、Git 刷新、重载）

~~~text
源 Buffer 变化（非本 Editor 发起）
  → 源订阅唤醒 MultiBuffer
  → MultiBuffer 拉取源净编辑，重建 excerpt/diff 投影并发布事件
  → Editor 观察组合变化，推进派生快照
  → 选择与滚动按源 Anchor 重新解析
  → EditorElement 重绘
~~~

### 12.3 显示配置变化（折叠、软换行宽度）

~~~text
Editor 修改 DisplayMap 的配置或折叠范围
  → DisplayMap 从受影响层开始同步，向下游传播 edit
  → 生成新的 DisplaySnapshot
  → Editor 的派生快照更新；选择（源 Anchor）与滚动（组合 Anchor）不受影响
  → EditorElement 按新显示拓扑布局
~~~

### 12.4 异步软换行重排

~~~text
结构变化 → WrapMap 急切插值出可用快照并输出插值 edit
  → 前台预算内完成则直接落地真实快照
  → 超时则后台重排；后台完成时以反转后的插值编辑叠加真实编辑
  → 输出「上次对外快照 → 当前真实快照」的净编辑
  → 显示链据此重建 Block 投影并重绘
~~~

### 12.5 Undo／Redo

~~~text
Editor 触发 undo/redo
  → Buffer 按历史节点从编辑日志回放
  → 走与普通编辑相同的订阅、组合同步、显示同步路径
  → Editor 按 TransactionId 从选择历史恢复对应选择
  → 发布与普通编辑一致的事件
~~~

## 13. 生命周期与资源管理

### 13.1 创建与销毁

- `LanguageBuffer` 由 `Project` 的文件边界或输入场景创建并直接持有文本 `Buffer`；创建时启动解析任务。
- `MultiBuffer` 由 `Editor` 或工作区创建，可以包含一个或多个源文档；源文档生命周期由 `Project` 的弱索引协调。
- `DisplayMap` 与 `Editor` 同生命周期；其中的异步 WrapMap 由 DisplayMap 创建并持有，后台任务随实体销毁而取消。
- `EditorElement` 每次布局临时创建，不持有长期资源。

### 13.2 订阅

- 订阅关系必须明确方向：下层状态变化通知上层，上层消费增量或重新读取；不得让下层反向依赖上层的消费者。
- 订阅的销毁与实体销毁一致；实体销毁后不得再投递事件。
- 惰性同步（读取时按版本拉取）与事件通知可以并存，但必须明确谁负责推进状态；同一状态不得同时由「事件回调」和「显式刷新」两条路径推进。

### 13.3 后台任务

- 后台任务必须可取消，并与拥有它的实体同生命周期。
- 后台结果安装前必须校验版本；过期结果必须丢弃。
- 后台任务不得直接写上层状态，必须回到拥有该状态的实体，经唯一入口安装。

### 13.4 持久化

- 只持久化稳定、可恢复的事实，不序列化运行时实体、句柄或可重建缓存。
- 每类持久化数据只有一个所有者模块；其他模块通过其 API 使用。

## 14. 依赖方向与越界禁止

### 14.1 允许的依赖方向

~~~text
zcv-text
  ← zcv-language
  ← zcv-buffer-diff（文本与语言语义域）
  ← zcv-multi-buffer（组合文档）
  ← zcv-editor（显示、交互、渲染）
  ← zcv-project / zcv-workspace / zcv（文件、工作区与应用装配）
~~~

- 文本层不依赖任何编辑器相关 crate。
- 语言层只依赖文本层与设置；不依赖组合文档、编辑器或 UI。
- 组合文档层依赖文本、语言与 diff 能力域；不依赖编辑器、UI 或工作区。
- 编辑器核心（显示、交互、渲染）依赖文本、语言、组合文档与主题／UI 原语；通过明确的 Item／Provider 协议与工作区集成。
- 文件与工作区层协调文档生命周期与窗口容器；不得把文本、语法或组合文档的可写权威上移。

### 14.2 禁止的依赖与职责越界

- 文本层不得依赖编辑器、UI、语言、组合文档、项目或工作区。
- 语言层不得依赖组合文档、编辑器或工作区。
- 组合文档层不得依赖编辑器、UI 或工作区。
- 显示投影层不得依赖编辑器；它是被编辑器消费的独立投影。显示投影不得持有文本、excerpt 或 diff 的可写权威，也不得直接读取比其下层更低的原始批次。
- `Editor` 不得维护第二份文本、excerpt、显示行权威。
- `EditorElement` 不得成为选择、滚动或历史的权威，也不得写回文档、选择或显示状态；它可以把几何缓存写回 `Editor` 的缓存字段。
- 显示投影与渲染可以位于同一 crate 并互相引用（渲染读取显示投影，编辑器构造渲染），但依赖必须保持单向语义：投影不感知交互状态，渲染不拥有权威状态。
- 文件／项目层不得依赖组合文档，也不得为 diff、保存、搜索分别物化同一文件的第二份可写文档。
- 任何层都不得引入 LSP、协作或远程能力，也不得为它们预建 trait、事件总线或兼容层。

## 15. 核心不变量

以下清单是长期约束，编号稳定，供代码与评审引用：

文本层：

- T-1 `Buffer` 是文本内容、版本与历史的唯一可写所有者。
- T-2 任何文本修改都经过带版本校验的事务。
- T-3 `Anchor` 是不可变值，在目标快照上重新定位；长期锚点解析只依赖不衰减坐标索引，不依赖被预算裁剪的带文本编辑日志。
- T-4 `Snapshot` 不可变且与版本一致。
- T-5 编辑日志是净编辑的唯一事实。
- T-6 不存在旁路写入文本的路径。
- T-7 版本抽象必须支持历史可见性、任意跨度净编辑与历史文本重建。
- T-8 锚点解析绑定目标快照；代际被 reset／基线替换、目标更旧或端点退出投影时显式失败，调用方丢弃或重锚，不得猜测坐标。
- T-9 后台派生快照只在版本校验通过后原子替换。

语言层：

- L-1 文本与语法快照同版本。
- L-2 「已插值版本」与「已解析版本」语义分离，过期解析结果不安装。
- L-3 同一文档同时只有一个后台解析任务。
- L-4 语法查询只消费匹配版本快照，结果携带版本。
- L-5 高亮缓存有界、可丢弃、随版本失效。
- L-6 语言设置按 buffer／language 解析并在快照中下发，不在上层复制。
- L-7 解析等非文本状态变化有独立元数据版本，必须推进上层快照链。
- L-8 尚未加载的注入语言保留为待解析层，不静默丢弃。

组合文档层：

- M-1 不持有源文本的第二份可写副本。
- M-2 excerpt 顺序与 diff 投影只有一个权威结构；投影树的未删除输入必须等于 excerpt 树的文本摘要。
- M-3 组合坐标查询通过连续 cursor 推进。
- M-4 结构重建后由源 `Anchor` 重新解析。
- M-5 文本与元数据变化都推进快照链。
- M-6 源编辑与组合编辑走同一源事务路径。
- M-7 excerpt 有序不重叠；除最后一个外都带尾部换行，最后一个不带。
- M-8 组合事务只保存源事务身份映射；结构变更在文本事务之外。
- M-9 编辑落点只允许可写且非删除段的内容。

显示投影层：

- D-1 层顺序固定，每层只依赖其下层。
- D-2 每层提供快照、正反坐标转换、cursor 与增量 edit 映射。
- D-3 `Edit` 表示待失效区域，不承诺精确差量。
- D-4 `DisplaySnapshot` 内部嵌套下层同版本快照。
- D-5 同步只有一个入口，快速路径覆盖全部影响结果的状态。
- D-6 结构重建后由源 `Anchor` 重新解析位置。
- D-7 显示热路径不物化整行或整份文本。
- D-8 每层变换树的 input 精确覆盖下层；同构段不合并。
- D-9 折叠有序不重叠；折叠身份单调唯一，范围用 `Anchor`。
- D-10 虚拟块层的输入行数与软换行层一致；显示行数与投影一致。
- D-11 跨层转换必须显式给出 Bias。
- D-12 只有软换行层是异步实体；插值态与后台任务必须同时成立。

交互层：

- E-1 `Editor` 不拥有第二份可写文本、excerpt 或显示行权威。
- E-2 派生快照整体替换；选择不在派生快照中，选择权威是选择集合。
- E-3 所有文本修改进入统一事务路径。
- E-4 长期位置状态保存 `Anchor`，消费时按当前快照解析。
- E-5 文本历史在文本层、选择历史在 `Editor`，通过 `TransactionId` 关联。
- E-6 编辑事件只在真实事务提交时发布。
- E-7 所有文档形态共用同一个 `Editor` 管线。
- E-8 所有选择变更经唯一入口；锚定吸附与合并规则固定。
- E-9 事务结果落地顺序固定为「文本 → 显示 → 选择」。

渲染层：

- R-1 `EditorElement` 不写回文档、选择或显示权威状态。
- R-2 布局只读取当前版本链一致的快照。
- R-3 像素缓存随版本失效，可丢弃、可重建。
- R-4 热路径不物化整份或整行投影文本。

工程边界：

- P-1 同一路径／修订只有一个权威文档实体。
- P-2 Project 不把可写权威上移为产品层状态。
- P-3 Workspace 不复制 Item 的领域状态。
- P-4 Project 的文件边界不依赖组合文档。

## 16. 新功能放置指南

按顺序回答以下问题：

1. 它改变的是文本事实吗？→ 文本层事务。
2. 它需要语法／Tree-sitter 信息吗？→ 语言层查询与快照结果。
3. 它改变组合文档的内容组织、excerpt 顺序或 diff 投影吗？→ 组合文档层。
4. 它只改变文本如何显示（折叠、tab、换行、虚拟块）吗？→ 显示投影层。
5. 它是交互状态或用户操作编排吗？→ `Editor`。
6. 它只影响当前帧的布局、绘制或像素命中吗？→ `EditorElement`。
7. 它是文件、修订、保存或窗口容器吗？→ `Project`／`Workspace`。

补充规则：

- 新增文档形态时，先问「能否用同一个 `Editor` + 不同的文档模型／显示投影表达」。默认可以，且必须这样做。
- 新增可折叠、可跳转、可高亮的位置时，优先保存 `Anchor`，不保存裸偏移。
- 新增跨层读取时，先确认是否已有权威快照可用；若需要新事实，先决定所有者，再决定派生物。
- 新增异步能力时，先确定版本校验与结果安装入口，再实现。
- 新增语言能力时，优先扩展 `.scm` 查询与语言层结果类型，不建立 LSP 抽象。

## 17. 与原型的能力裁剪登记

下表记录被裁剪能力及其对应的架构后果。裁剪的判据是「该架构的根本存在理由是否为已舍弃能力」。

| 被裁剪能力 | 原型中的架构 | Zcv 的处理 | 保留的核心职责 |
| --- | --- | --- | --- |
| 实时协作（多副本 CRDT） | 文本 Buffer 由 fragment/insertion 树、replica id、Lamport 时钟、延迟操作队列组成，支持并发插入与合并 | 文本存储改为本地 rope；版本从多副本向量收缩为本地单调版本；删除 replica、多副本合并与远程编辑设施 | 保留版本抽象及其历史查询能力（任意跨度净编辑、历史可见性、历史文本重建）、快照、`Edit`/`Patch`、`Anchor`、事务、历史、订阅与增量协议 |
| 协作选择与光标 | `Editor` 中的协作者选择、跟随者、光标广播、协作会话 | 删除协作选择、跟随与广播状态；只保留本地选择、选择历史与光标绘制 | 保留选择集合、选择历史、事务关联、光标与焦点生命周期 |
| 远程开发 | 远程 `BufferStore`、远程路径、参与者协商、远程传输协议 | `BufferStore` 只按本地路径复用本地文档；删除远程/协议状态 | 保留「路径 → 文档实体」的索引、打开/保存/重载生命周期与弱引用复用 |
| LSP 客户端 | `language::Buffer` 内的服务器诊断、服务端 semantic token、代码操作、hover、语言服务器 Store 与注册句柄 | 删除 LSP 客户端及其存储；语言层只保留 Tree-sitter 语法、查询与语言设置 | 保留「文本与语法一致快照」、增量解析、语法查询、语言设置与缓存边界 |
| 协作/远程的事件与协议 | 为协作/远程存在的 proto、事件协议、通用抽象 | 不保留对应抽象，也不为未来预建兼容层 | 保留编辑器核心的事件与订阅方向 |

裁剪后允许保留的差异只限于上表直接结果；其余剩余架构必须与原型同方向。

## 18. 当前实现与目标架构的差距登记

差距分四类：尚未复刻、复刻偏离、合理裁剪、实现差异。本表只登记需要长期跟踪的条目，新增差距应在此登记并在消除后删除。

### 18.1 尚未复刻（应进入目标架构）

- 完整的多光标交互状态：添加多个选择的分组状态、选择下一个/上一个匹配的状态、列选择状态。它们属于 `Editor` 的帧内交互状态，与持久选择集合分离；当前阶段不实现（见第 1.2 节），实现时不得做成第二套编辑流程。

以上未标注「当前阶段不实现」的条目均为已登记的待完成项。

### 18.2 复刻偏离（应按目标修正）

（当前无登记条目。）

### 18.3 合理裁剪（保留）

- 文本存储是本地 rope，不是 CRDT 片段树；版本是本地单调推进，不是多副本向量。
- 无远程序列化、无协作者选择、无跟随者、无远程参与者状态。
- `BufferStore` 只做本地路径索引，不含远程协商与传输。
- 语言层不含 LSP 客户端、服务器 Store、服务器诊断、服务端 semantic token、代码操作与 hover。
- 用只读预览文档替代分支缓冲；不引入协作副本。

### 18.4 实现差异（无需为形式一致而修改）

- 文本存储用 rope 与两阶段提交，而不是 CRDT 片段树；只要保留版本、锚点、增量与历史查询契约即可。
- 后台 diff 计算物化全文；它不在编辑或显示热路径。
- `Editor` 用多个改变入口表达不同编辑语义（普通、编辑后重算选择、编辑后读投影再定选择），语义等价。
- `Editor` 与 `EditorElement` 位于同一 crate 并相互引用；只要渲染层不成为任何权威状态的拥有者、几何缓存只写回 `Editor` 的缓存字段，即符合边界。
- 单源组合文档的历史委托给源文档历史、多源组合文档使用组合历史；两条路径共享「事务身份 + 源 Anchor」语义。
- 高亮缓存的具体淘汰策略、异步软换行的预算值、坐标 newtype 的具体命名属于实现细节。
- 硬 Tab 层不建立持久列变换树、按行即时展开 tab 计算显示列（8.2 的刻意例外）；但它仍产出本层行级 `TabEdit`，`WrapMap` 只消费直接下层的 `TabEdit`。

## 19. 验证与维护

### 19.1 修改编辑核心时的验证

- 文本层：版本失配、事务原子性、编辑日志净编辑、Anchor 跨版本推进、undo/redo 与保存点。
- 组合文档层：excerpt 顺序变化、源编辑、diff 展开/折叠、结构重建后源 Anchor 重解析、纯元数据变化推进快照。
- 显示投影层：每层正反坐标、层间增量传递、折叠/换行组合、异步重排落地、快速路径不丢同步。
- 显示装饰：搜索命中、diff hunk、宿主 hunk 与折叠候选在显示版本上按视口查询；staging、展开态等非文本变化必须推进组合元数据版本，使按显示版本键控的装饰不会陈旧。
- 交互层：所有文档形态共用编辑入口、选择在投影重建后跟随、undo/redo 同时恢复文本与选择、事务事件只在真实提交时发布；显示装饰不在 `Editor` 中形成并列的显示坐标权威。
- 渲染层：可见范围读取、命中测试、像素缓存随版本失效、热路径不物化整份文本。
- 依赖方向：新增依赖不得违反第 14 节；发现越界先修正边界再提交。

### 19.2 文档维护

- 本文只记录架构契约与不变量；模块职责与使用方式写在对应 crate 的 `README.md`。
- 当修改改变职责、所有权、生命周期或依赖方向时，同步更新本文与对应文档。
- 差距登记是临时事实：条目消除后应删除，而不是保留历史说明。
