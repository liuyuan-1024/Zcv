# 函数式组件开发流程

> 基于 zcv 现有实践（`bar_frame`、`render_body`、`pip`、`render_dock`、`tree::render_row_base` 等）提炼的标准。
> 纯函数式渲染组件一律按此流程推进，不做 Entity 化或 Builder 化。

---

## 一、定义与定位

**函数式组件 = 提取 Div 重复构建逻辑的纯函数。**

- 输入只有函数参数，无内部状态
- 输出为 `Div`（或 `Stateful<Div>`、`Vec<AnyElement>`）
- 不实现任何 GPUI trait（Render、IntoElement、Element）
- 在父级 Render 函数内部调用

### 典型产出

| 类别 | 特征 | 示例 |
|---|---|---|
| 外壳函数 | 包裹内层，提供容器和样式 | `bar_frame(edge)`, `row_skeleton(depth)` |
| 分隔辅助 | 单线条，纯视觉 | `bar_divider()`, `render_dock_divider(area)` |
| 渲染函数 | 条件渲染 | `render_body(...)`, `render_dock(state)` |
| 构建辅助 | 收集 Vec 或编排布局 | `cluster(items)`, `join_groups(groups)`, `region(items, align)` |

### 与 Builder 组件（如 Glyph）和 Entity 组件的区别

| 维度 | 函数式组件 | Builder 组件 | Entity 组件 |
|---|---|---|---|
| 核心 | 消除布局重复 | 封装交互原语 | 封装生命周期状态 |
| struct 定义 | 不需要 | 需要 | 需要 |
| 实现 trait | 不需要 | 实现 `IntoElement` (+ 关联 traits) | 实现 `Render` |
| 内部状态 | 无 | 构建期持有参数 | 跨帧持有状态 |
| 返回类型 | `Div` 等具体类型 | 自身 (Builder) | `impl IntoElement` |
| 父级用法 | `组件.child(fn(...))` | `组件.child(Glyph::icon(...))` | `组件.child(entity.clone())` |
| 典型规模 | 1–10 行 | 80–200 行 | 200+ 行 |

**判断准则：** 这坨代码解决的是"长得一样"的问题，还是"行为一样"的问题？

- **长得一样** → `Div` 结构重复 → 函数式组件
- **行为一样** → 交互逻辑重复 → Builder 组件或 Entity 组件

## 二、开发三步流程

### 第 1 步：计算参数

确定函数的输入参数。所有数据必须通过参数传入，不访问任何外部状态。

```rust
// 参数只有枚举，控制变体
pub(crate) fn bar_frame(edge: BarEdge) -> Div

// 参数是渲染期快照 + 回调，不持有状态
pub(crate) fn render_dock(area: DockArea, state: &DockState, panel_content: &PanelContentFn) -> Div

// 参数是纯数据值，由调用方提取
pub(crate) fn render_row_base(depth: usize, is_dir: bool, expanded: bool, name: &str) -> Div

// 无参数：纯视觉固定元素
pub(crate) fn bar_divider() -> Div
```

**规则：**
- 不接收不使用的参数
- 不接收 `&mut Context<Self>` 或 `&mut Window`（那是 Entity 的事）
- 纯视觉函数不走 `cx` 或 `window`

---

### 第 2 步：确定返回类型

| 返回类型 | 适用场景 | 调用方后续操作 |
|---|---|---|
| `Div` | 最常用，只有一个"根节点" | 可继续链式 `.child()` `.id()` 等 |
| `gpui::Stateful<gpui::Div>` | 函数内包含交互状态（group hover、on_click 等） | 同上 |
| `Vec<AnyElement>` | 构建一组平级元素 | 传入 `.children(vec)` |
| `impl IntoElement` | 返回类型不是 Div（Svg 等），或需封装内部细节 | 直接用作子元素 |

```rust
// 最常用：返回 Div，调用方可继续链式添加 child
pub(crate) fn bar_frame(edge: BarEdge) -> Div {
    let frame = div()
        .flex().flex_row().items_center()
        .w_full().px(space::S8).py(space::S6);
    match edge {
        BarEdge::Top => frame.border_b_1().border_color(color::current().border_variant),
        BarEdge::Bottom => frame.border_t_1().border_color(color::current().border_variant),
    }
}

// 有交互：返回 Stateful<Div>，on_click 等在此生效
pub(crate) fn pip(pip: Pip, active: bool) -> gpui::Stateful<gpui::Div> {
    let (fill, border) = pip.palette(active);
    div()
        .id(pip_id)
        .size(px(12.0)).rounded(radius::FULL).bg(fill)
        .border_1().border_color(border)
        .cursor_pointer()
}

// 集合返回：Vec<AnyElement> 供 .children() 消费
fn join_groups(groups: Vec<Vec<AnyElement>>) -> Vec<AnyElement> {
    let mut out = Vec::new();
    for group in groups {
        if !out.is_empty() {
            out.push(bar_divider().into_any_element());
        }
        out.extend(group);
    }
    out
}
```

**规则：**
- 调用方需要继续链式 `.child()` 时，返回 `Div`
- 返回集合时用 `Vec<AnyElement>`，不返回 `Vec<Div>`（一组元素最终类型不一）
- 不返回 `AnyElement` 单个元素（用 `Div` 更精确，调用方省掉 `into_any_element()`）

### 第 3 步：调用

在组件的 `Render::render` 或其他函数式组件内部调用：

```rust
// Entity 的 Render 中调用
impl Render for TopBar {
    fn render(&mut self, window: &mut Window, _cx: &mut Context<Self>) -> impl IntoElement {
        bar_frame(BarEdge::Top)          // ← 函数式组件
            .id("top-bar")
            .child(cluster(leading_slots(window)))   // ← 集合函数式
            .child(drag_spacer())
            .child(cluster(trailing_slots()))
    }
}

// 函数式组件嵌套调用
fn render_body(layout: &LayoutSnapshot, panel_content: &PanelContentFn) -> Div {
    let mut row = div().flex_1().flex().flex_row().size_full();
    if layout.left_dock.is_visible() {
        row = row
            .child(render_dock(DockArea::Left, &layout.left_dock, panel_content))
            .child(render_dock_divider(DockArea::Left));    // ← 另一个函数式组件
    }
    row.child(center_col)
}
```

## 三、文件放置规则

- 如果函数式组件只被一个 Entity 使用：放在该 Entity 的模块文件（或 `render.rs`）中，不新建文件
- 如果函数式组件被多个 Entity 共享：放在职责明确的公共模块下（如 `ui/tree.rs`）
- **函数式组件不走独立的文件**。它们是提取的结果，文件应当由 Entity 模块组织决定，而不是由函数式组件数量决定

---

## 四、与 Builder 组件的边界

当函数式组件开始需要多个可选参数、且每个参数有默认值时，考虑升级为 Builder 组件：

```rust
// 函数式 — 参数少且固定
pub(crate) fn bar_frame(edge: BarEdge) -> Div

// Builder — 参数多且组合自由（示例）
pub(crate) struct Glyph { ... }
impl Glyph {
    pub(crate) fn icon(id, path) -> Self
    pub(crate) fn tooltip(self, label) -> Self
    pub(crate) fn on_click(self, handler) -> Self
    pub(crate) fn color(self, color) -> Self
}
// 实现 IntoElement 以便直接传入 .child()
```

**升级触发条件（需同时满足）：**
1. 有 3+ 个可选配置项
2. 每个配置项都有合理的默认值
3. 存在 2+ 个不同的调用方需要不同组合
