# Zcv 编辑器架构维护

以 [`docs/编辑器架构.md`](../../../docs/编辑器架构.md) 为 Zcv 编辑器核心的目标架构契约。当前实现只提供待审计的事实，不能反向定义目标；Zed 是原型，文档记录的 Zcv 裁剪边界与稳定不变量优先于文件名、代码形状和局部便利。

先判断用户要的是只读审计、迁移规划、明确修改还是代码评审。审计、解释和评审不授权修改；实现、重构、迁移或修复等明确请求才授权在目标边界内修改代码。

## 读取架构契约

先读取仓库及目标目录的 `AGENTS.md`，再按任务范围读取架构文档：

- 所有任务都读取第 1–4、12–19 节，确认原型与裁剪边界、分层、权威状态、坐标与版本语义、传播路径、生命周期、依赖方向、核心不变量、差距登记和验证要求。
- 文本事实、事务、历史、版本、编辑日志、Anchor：读取第 5 节。
- Tree-sitter、语法快照、解析任务、语言设置：读取第 6 节。
- excerpt、组合坐标、diff 投影、组合事务：读取第 7 节。
- Fold/Tab/Wrap/Block、显示坐标、投影增量：读取第 8 节。
- 选择、滚动、输入法、搜索、编辑事务与事件：读取第 9 节。
- 布局、绘制、shaping、像素命中：读取第 10 节。
- 文件文档实体、Git 修订、Item、Pane、Workspace：读取第 11 节。
- 跨层任务读取所有受影响层及其直接上下游；全面架构审计或迁移必须完整读取全文。

不要把第 18 节的“当前差距”误当作稳定架构。第 1–17 节定义目标与不变量，第 18 节记录可增删的当前事实，第 19 节定义维护方式。

## 目标管线

始终围绕唯一数据流推理：

```text
Buffer
  → LanguageBuffer
  → MultiBuffer
  → DisplayMap（Fold → Tab → Wrap → Block）
  → Editor
  → EditorElement

Project / Workspace：创建、复用并装配文档实体与 Editor Item，不进入内容投影链
```

逐层确认六项契约：职责、唯一可写所有者、不可变快照、坐标空间、增量输入/输出、创建与销毁生命周期。结论必须能对应架构文档中的稳定不变量编号（`T-*`、`L-*`、`M-*`、`D-*`、`E-*`、`R-*`、`P-*`）。

## 不得弱化的跨层约束

- 普通文件、搜索结果、diff、预览和组合文档共用一个 `Editor` 与同一套交互、事务、显示和渲染管线；差异收敛在文档模型、投影和只读能力。
- 一个事实只有一个可写所有者。上层只持有不可变快照、`Anchor`、可丢弃缓存或领域句柄，不维护文本、excerpt、显示行、选择等影子权威。
- 长期位置保存 `Anchor`；裸 offset、point、row 和显示坐标只在显式快照与转换边界内使用。不同坐标空间使用不同类型，跨层转换明确 `Affinity`、`Bias` 或失败语义。
- 快照不可变并固化下层同版本快照。文本变化与元数据变化都必须推进快照链，不能只比较文本版本。
- 变化沿“旧快照 + 增量 → 新快照 + 上层增量”向上传播。不得用全文物化、全量投影重建、跨层读取原始批次或并行刷新路径代替增量协议。
- 增量入口不得静默回退到全量。全量只允许作为显式边界操作存在——构造、整体替换、配置切换、低频重命名——并且必须命名清楚、只有单一入口。推导失败或边界不匹配时，应修正推导本身或让不变量直接失败；不得用“算不出来就整份重建”的兜底掩盖协议偏离，它既会隐藏真实偏差，也会留下无法回收的残留状态。
- 文本修改只有一条带版本校验的事务路径；事务结果按“文本 → 显示 → 选择”落地。undo/redo、输入法、替换和结构化编辑复用这条路径。
- 每项派生状态只有一个推进入口。订阅负责唤醒，版本差负责拉取；事件回调与显式刷新不能同时写同一状态。
- 后台任务由其领域实体拥有并随之取消；安装结果前校验版本，过期结果丢弃，不能直接写上层状态。
- 依赖只从上层指向下层；Project/Workspace 负责生命周期与装配，不上移文本、语法、组合文档或显示投影的可写权威。

## 对齐 Zed 与裁剪能力

涉及成熟编辑器能力时，读取 `/Users/liuyuan/projects/zed` 中对应层的当前实现，核对模块职责、状态所有权、数据流、生命周期、坐标与增量协议。对齐的是架构契约，不是文件名或代码形状。对应层的增量入口没有“推导失败就整份重建”的兜底；Zcv 中出现的这类分支本身就是对齐差距。

只裁剪实时协作、远程开发和 LSP 及其专属基础设施。版本、快照、Anchor、历史可见性、任意跨度净编辑、增量解析、组合文档与显示投影不是协作专属能力，不能随之删除。语言智能继续使用 Tree-sitter 与 `.scm` 查询，不预建 LSP 接口。

任何偏离都必须落入架构文档第 1.3 节允许的两类之一，并给出证据。当前实现更简单、改动较大、调用方多或暂时只有一个消费者都不是偏离理由。

## 工作流

- 审计、解释、规划或评审：读取 [references/architecture-assessment.md](references/architecture-assessment.md)。
- 明确要求实现、迁移、重构或修复：读取 [references/architecture-migration.md](references/architecture-migration.md)。先完成目标边界与上下游审计，再修改。
- 同一任务包含审计与实施时，两份参考都读取；先产出有证据的差距与目标设计，再一次性迁移所有调用方并删除旧路径。

若用户指定的局部修改暴露底层抽象错误，以完成目标架构所需的跨 crate 范围为准，不叠加 fallback、兼容层、双轨实现或一次性旁路。若正确方向无法从架构文档、Zed 原型与已声明产品范围唯一确定，或必须越过用户明确排除的能力域，停止并请求方向。

## 交付

最终说明：涉及的层和不变量、原有数据流、修改后的唯一权威与增量路径、删除的旧概念、实际执行的定向验证，以及仍未验证的运行时或平台边界。不要用文件数、代码行数或宽泛测试通过代替架构证据。
