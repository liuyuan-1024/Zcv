# 桌面端高亮架构

> **设计立场**：zom 的「高亮」不止语法高亮，还有选区、搜索匹配、当前行、diagnostics、hover 和折叠占位等。本手册规定整套高亮的**全局架构**——producer / composer 分层、装饰协议、叠加规则、优先级档位。具体某一类高亮的产出机制（如语法）拆到独立手册。
>
> 由此推论：
>
> - 不允许某个 feature 自起一条「自己的高亮渲染通路」。所有上屏高亮必须经由本手册定义的合成层。
> - 不允许 producer 之间直接互相感知（搜索不读 syntax layer、选区不读搜索 layer）。
> - 装饰协议是 producer 与 composer 之间的最小公共面，不向 producer 暴露 composer 内部数据结构。

## 参考

- [`桌面端语法高亮.md`](桌面端语法高亮.md)：本手册的第一个 producer 子系统。

## 一、定位与边界

- **是什么**：桌面端「上屏前的最后一层」——把多个 producer 投递的区间装饰合并成每个 grapheme cell 的最终前景 / 背景 / 下划线 / 边框 / 字重。
- **不是什么**：
  - 不产任何高亮数据。所有装饰来自 producer。
  - 不解析颜色。`StyleClass` 由 theme 在 desktop `shared/theme.rs` 解析为具体 `Rgba` / 字重。
  - 不裁剪区间到 viewport。viewport 切片由 EditorView 在调 composer 前完成。
- **在分层中的位置**：

```text
┌────────────────────────────────────────────────────────┐
│ EditorView 字符层渲染（GPUI 绘制每个 cell）              │  L3
├────────────────────────────────────────────────────────┤
│ HighlightComposer                                       │  本手册主体
│   按 priority 合并多 producer 的 Decoration → cell 样式 │
├────────────────────────────────────────────────────────┤
│ Producers（各自独立、互不感知）                          │
│   syntax / selection / search / diagnostics / ...       │
└────────────────────────────────────────────────────────┘
```

## 二、原则：producer 分散 / composer 统一

- **生产层（producer，分散）**：每类高亮自己拥有数据源、刷新触发、失效语义、版本对齐。syntax 走 [`桌面端语法高亮.md`](桌面端语法高亮.md) 的 provider 子系统；选区由 `view` 模块产；搜索由 search 命令产；diagnostics 由 LSP 产；依此类推。producer 之间互不感知、互不读写对方数据。
- **合成层（composer，统一）**：渲染端有且只有一个 `HighlightComposer`，按统一协议消费全部 producer 的产出，按优先级叠加，决定每个 grapheme cell 的最终样式。

**理由**：

- 完全分散：选中区里有搜索词、搜索词命中报错行、hover 强调当前行……每类重叠都要重新发明 z-order、区间合并、颜色覆盖规则，落地一定出 bug。
- 完全统一：搜索 / 选区被迫绕道 syntax 的 `BufferVersion` / `ChangeSet` / provider 生命周期管线；扩展新高亮（hover、diagnostics）成本非线性上升。
- 本分层：producer 各自演进，composer 是唯一懂「叠加规则」的地方。

## 三、Producer 清单

当前枚举所有合法 producer。未列入清单的不允许直接推 composer——必须先在本手册补一行。

| Producer | 拥有方 | 触发 | 数据形态 |
|---|---|---|---|
| syntax | `zom-workspace` 语法高亮子系统 | buffer 编辑 | `BufferSyntaxTree`（共享 slot） |
| selection | `view` 模块 | view selection 变更 | view 内的 selection range 集合 |
| search | `zom-command` 搜索命令 | 搜索词 / 范围变更 | match range 集合 + current index |
| diagnostics | LSP 客户端（`zom-workspace`） | server push | range + severity |
| hover-emphasis | 命令侧（goto-definition / find-references 等） | 临时触发 | range + 短生命周期 |
| current-line | composer 自合成（不算独立 producer） | view caret 移动 | 由 caret 推导 |
| fold-placeholder | `view` 模块 折叠 | 折叠变更 | 占位区间 |

`current-line` 由 composer 内部从 view 的 caret 直接推导，不走 producer 投递路径——它是 caret 的几何派生，独立 producer 化只会增加同步成本。

## 四、装饰协议

producer 与 composer 之间的最小公共面。producer 把产物表达为一组 `Decoration` 投递给 composer；composer 不知道 producer 是谁。

> 类型定义参见 [`zom-desktop/src/editor/highlight/mod.rs`](../../zom-desktop/src/editor/highlight/mod.rs)。

- `StyleClass` 是 theme 端识别样式的索引键，命名与 [`桌面端视觉系统.md`](桌面端视觉系统.md) 的 token 命名同源（如 `"selection.background"` / `"diagnostic.error.underline"`）。composer 不解析；theme 端解析为 `Rgba` / 线型 / 粗细。
- `priority` 见 §六。
- 区间靠 `range` 自己携带；composer 内部按需切分到 grapheme。

**Producer 投递接口（composer 端定义）**：

> 类型定义参见 [`zom-desktop/src/editor/highlight/compose.rs`](../../zom-desktop/src/editor/highlight/compose.rs)。

- 同一 `SourceId` 的产物在 composer 内独立存活；不同 source 互不覆盖彼此的存储。
- `replace_all` 是最常用形态；`replace_range` 留给 syntax / diagnostics 这类有增量能力的 producer。
- producer 不需要自己 remap edit 后的区间——若 producer 把产物寄存在 engine 的 `MetadataLayer`（如 syntax），engine 自动 remap；其他 producer 自己负责重投。

## 五、合成规则

composer 在每次绘制前对当前 viewport 内涉及的所有 `Decoration` 做合并，输出每个 cell 的最终样式。规则按 `DecorationKind` 拆开，互相正交：

| Kind | 合成规则 |
|---|---|
| `Foreground` | 取覆盖该 cell 的最高 `priority` 一份；其余丢弃 |
| `Background` | 多份按 `priority` 升序自下而上叠加（详见[`桌面端视觉系统.md`](桌面端视觉系统.md)） |
| `Underline` | 多份共存，按 `priority` 决定绘制顺序；同 `StyleClass` 合并 |
| `Border` | 多份共存，独立绘制 |
| `Weight` / `Slant` | 同 kind 取最高 `priority` 一份 |

- `Foreground` 与 `Background` 正交：背景半透明叠在 cell 上，字色仍由 `Foreground` 决定。这是 syntax 字色在选区 / 搜索高亮下仍可读的底层原因。
- 同 `kind` 同 `priority` 同 `range` 重叠：**后入者覆盖**。允许这种情况发生但不依赖跨 producer 协调——producer 之间不能用「我比你晚推」做隐式握手。
- 不允许 producer 在 `Decoration` 里要求「我必须盖在 X 上」之类的相对约束。所有覆盖关系只能通过 `priority` 表达。

## 六、优先级档位

`priority` 的具体数字可调，**档位顺序是不变量**。producer 在自己的档位内部分配，跨档位调整必须经过本手册修订。

| 档位 | 用途 |
|---|---|
| 0 – 99 | syntax 前景色 |
| 100 – 199 | 折叠占位 / 不可见字符提示 |
| 200 – 299 | current-line 背景 |
| 300 – 399 | 选区背景 |
| 400 – 499 | 搜索高亮背景（current match 比 other match 高 50） |
| 500 – 599 | diagnostics（hint < info < warning < error，每级 +10） |
| 600 – 699 | hover-emphasis / goto 临时强调 |
| 900+ | 保留 |

- 档位之间留出余量，便于子档细化。
- 跨产品形态的档位调整需在本手册显式翻转，而非在某个 producer 内部偷改 `priority`。

## 七、与语法高亮的对接

语法高亮（[`桌面端语法高亮.md`](桌面端语法高亮.md)）是本架构的**第一个也是最复杂的 producer**，对接点：

1. 后台 worker 把 reparse 后的 `Arc<BufferSyntaxTree>` 写共享 [`BufferSyntaxTreeSlot`]；主线程编辑入口同步 `tree.edit` 推坐标，让首帧 paint 拿到的 tree 已对齐新 snapshot。
2. composer 在合成前从 slot `load()` 出当前 tree，对 viewport 跑一次 tree-sitter Query 出 `(range, HighlightSpan)` 列表，把每个 `HighlightSpan` 翻译成一条 `Decoration { kind: Foreground, style: theme(name), priority: 0..100 }`。
3. theme 按完整 name → 点分前缀 → 默认前景色逐级回退查询，**回退链保证任意 name 必有 fallback**（详见[`桌面端语法高亮.md`](桌面端语法高亮.md)）。
4. 其他 producer 不读 syntax 子系统、不写 syntax 子系统。

`BufferSyntaxTree` 是 syntax 这一个 producer 的内部存储选择——其他 producer 自管数据形态（如选区 / 搜索的内存集合），后投递 composer。

## 八、生命周期与失效

- composer 与 EditorView 同生命周期。view 关闭 / buffer 关闭 → composer 释放，所有 producer 推送丢弃。
- producer 的 `clear(source_id)` 必须幂等。重复 clear 不报错。
- buffer 发生编辑时，composer 不主动 remap 区间——producer 自身负责重投或依赖 `MetadataLayer` 的 remap。composer 在收到下一次 `replace_all` / `replace_range` 前继续用旧区间渲染（短暂的视觉不一致可接受，比 composer 自作主张 remap 错位的代价低）。
- view 滚动 / viewport 变化 → composer 只重新切片，不触发 producer。

## 九、测试要求

| 模块 | 测试形态 |
|---|---|
| 合成规则 | 表驱动：给定 N 条 `Decoration`，断言每个 cell 的最终 kind / style / priority |
| 优先级档位 | 单测覆盖每个相邻档位的边界（syntax vs 选区、选区 vs 搜索、搜索 vs diagnostics） |
| `replace_all` / `clear` 幂等 | 同 source 重复推同样产物结果一致；清空后再推等价于首次推 |
| viewport 切片 | 区间落在 viewport 内 / 横跨 / 完全在外三种情形 |
| theme 解析 | 由 `shared/theme.rs` 自测；composer 测试用 mock `StyleClass → 样式` 表 |

**不测**：

- GPUI 像素结果（由组件实现手册的 element 测覆盖）。
- 各 producer 自身正确性（在 producer 的手册 / 模块内自测）。

## 十、当前不做的事

- **跨 cell 装饰的几何效果**（环绕边框跨多行的圆角拼接、波浪线动画）——当前下划线 / 边框按 cell 直绘。
- **producer 间的协商接口**：不提供「告诉我前一档已经有什么了」的查询，避免 producer 之间产生隐式耦合。
- **运行时新增 `DecorationKind`**：kind 在编译期定枚举；新增需改本手册并扩枚举。
- **mini-map / 缩略图的高亮合成**：与 mini-map 一起推迟。
- **跨 view 的高亮同步**：每个 view 一个 composer；搜索 / 选区在多 view 间的可见性由 producer 决定要不要向多 view 推。
