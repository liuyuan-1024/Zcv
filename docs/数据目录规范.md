# 数据目录规范

> 规定 zcv 产生的配置与数据文件的唯一落盘目录。

---

## 一、唯一目录：`~/.zcv`

**所有**由 zcv 产生的配置文件、数据文件一律存放在用户主目录下的 `.zcv` 目录（即
`$HOME/.zcv`，Windows 下为 `%USERPROFILE%\.zcv`），不随各平台配置惯例漂移
（macOS 不用 `~/Library/Application Support/`，Linux 不用 `$XDG_CONFIG_HOME`）。

当前目录下的已知文件：

```text
~/.zcv/
├── settings.json        用户设置（zcv-settings 写入/监听）
└── recent_projects.json 最近项目列表（zcv-workspace 读写）
```

## 二、路径来源单一

配置目录的解析只实现一份：`zcv_settings::config_dir()`（`zcv-settings/src/settings.rs`）。
任何需要落盘文件的能力域通过依赖 `zcv-settings` 复用该函数，**不得**在各 crate 内
重新实现平台路径解析——避免出现两套解析、两个落盘目录的双轨。

新增需要落盘的数据文件时：

1. 确认文件路径由 `zcv_settings::config_dir()` 派生。
2. 在第一节的文件清单中登记文件名与所属能力域。
3. 若新文件的归属能力域与设置系统无关，仍复用 `config_dir()`，但可考虑把路径
   解析函数提取到更通用的位置后再登记（出现 ≥2 个独立消费者时）。

## 三、约束

- 目录本身按需创建（`create_dir_all`），不随安装预置。
- 文件读写失败不阻塞主流程：设置加载失败回退默认值，最近项目加载失败返回空列表。
- 本规范适用于整个 workspace。
