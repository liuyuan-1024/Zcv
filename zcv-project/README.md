# zcv-project

项目数据层：仓库发现、git 状态编排、文件 Buffer 生命周期与项目级搜索。

`Project` 管理项目根、目录快照（Worktree）、按路径复用的文档实体（`BufferStore`）与文件系统监听；`GitStore` 管理仓库与修订文本。窗口布局、Pane、Dock 与其他界面状态由 `zcv-workspace` 管理。

`Worktree` 的同级条目按目录优先、名称自然排序；比较字母时先忽略 ASCII 大小写，数字段按数值比较。若名称只在字母大小写上不同，则首个差异处的小写字母排在大写字母前。树形规则由 `zcv-path` 提供，变更树和项目差异组合文档也使用它。

文件快速打开通过 `Project::searchable_file_paths` 在后台取得候选路径；它与项目内容搜索共用文件收集与扫描排除规则。匹配、选择与结果展示由工作区组件负责，打开仍走 `Workspace::open_path` 和项目文档索引。

## 文档实体与所有权

- 文件到文档的索引保存弱引用；只要还有 `Editor` 或视图持有文档，就复用同一条文档链，最后一个使用者释放后整条链结束。
- 同一路径只有一个权威文档实体；打开、保存、重载与搜索都经同一条解码与建 Buffer 路径（`buffer_store` + `text_file`），不为同一文件物化第二份可写文档。
- 多文件差异装配在后台读取、解码并建立文本 Buffer，再由 `Project` 通过同一路径索引安装语言文档。并发期间若该路径已被其他入口打开，安装时复用现有实体。
- Git 修订文本（HEAD / index）、加载任务和代次由 `GitStore` 按 `(revision, path)` 唯一管理。同路径调用共享读取，被新刷新取代的调用等待最新读取；无关路径互不失效。文件删除或恢复仍复用组合文档已经引用的源实体。读取失败保留已确认文本，返回错误并由工作区统一提示，不能缓存为“修订缺失”。
- `GitStore` 按工作区文档身份共享冲突范围快照；源文本变化触发后台解析，只有与当前源版本一致的结果才发布给冲突视图。快照是可重建的派生数据，最后一个消费者释放后结束订阅和解析任务。
- 首次读取 Git 修订时，文本 Buffer 在后台建立，前台只安装语言文档并发布同代次的修订状态；已有修订文档继续通过版本化编辑更新。
- 文件监听按路径覆盖刷新修订；`.git` 元数据事件覆盖仓库内已消费的修订。状态枚举与增删行数只描述面板状态，不能用来判断 index 内容是否变化。
- 普通编辑器的 Git 差异资格由仓库归属与忽略状态判定，干净和未跟踪文件共用修订加载与 `BufferDiff`；index 修订已确认缺失时作为空参照参与暂存分类，尚未加载时不冒充空参照。
- 文件解码固定为「剥离 UTF-8 BOM、拒绝非法 UTF-8」，并调用文本内核的同一规则把 CRLF／孤立 CR 转为 LF；源 `Buffer` 也在构造、替换和编辑入口保持 LF 不变量。保存前按源语言解析的两项设置，依次在源文档事务中删除各行末尾的空格／Tab、将非空文件末尾的 ASCII 空白收成一个 LF；两项默认开启并可独立关闭。保存直接写入整理后的同版本快照，不在写盘阶段另行改写文本；写盘失败时整理后的编辑仍未保存。
- 文件事件由 `Project` 转发给受路径覆盖的存活文档；干净文档的后台重载在文件暂时不可访问时持续重试，并在安装前校验文本版本。未保存编辑不会被磁盘内容覆盖。
- 保存多个源文件前先检查全部文档的磁盘冲突，未经用户选择的冲突不写盘，避免部分文件先保存。显式覆盖写入当前快照；还原在后台读取磁盘，并且只在文档身份与版本仍匹配时安装到原实体。
- 单文件编辑器的显式保存会提交该文件，即使此前没有手动编辑；组合文档只保存脏的可写源文件。保存整理因此也适用于刚打开且缺少末尾换行的文件。

## 边界

- 项目根在窗口装配入口校验并规范化为 `AbsolutePathBuf`，`Project` 直接使用该路径；其他构造入口的路径规范化失败以错误返回。文件监听注册失败由项目记录并交给工作区提示。
- 不依赖 `zcv-multi-buffer` 或 `zcv-editor`；文件边界只面向文档实体与文本快照，不依赖组合文档。
- 不把文本、语法或组合文档的可写权威上移为产品层状态。
- 不引入协作、远程与 LSP。
- `Project::copy_path` 复制项目内条目；`Project::copy_external_path` 接收系统文件输入的源路径。两者共用后台复制、目标校验和条目变更通知，源文件保持不变。
