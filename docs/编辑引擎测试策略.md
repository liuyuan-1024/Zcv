# 编辑引擎测试策略

> 目标：为 `zom-engine` 保持一套低噪声、低 flaky、面向工业级纯文本编辑引擎底座的测试组织方式。

测试的重点不是证明某个临时实现细节存在，而是锁住编辑语义、不变量、错误边界和性能底线。默认用自动化机器契约覆盖核心能力，examples 只作为宿主接入和体感辅助。

## 核心原则

- 大部分测试验证纯编辑引擎逻辑。
- 默认通过 public API 测试外部可依赖契约。
- 只有 public API 无法覆盖的重要内部不变量，才进入 crate 内部测试。
- UI / GPUI / 人类体感验证不替代机器契约。
- 性能验证与正确性测试分开维护。
- 测试应保护长期语义，不锁死无关实现细节。

## 目录职责

```text
tests/      机器契约测试，CI 主体
examples/   可选交互式 testbed，验证宿主接入体感
benches/    性能基准和回归分析
src/tests/  可选内部测试，只测 public API 难覆盖的重要不变量
```

根本分工：

```text
tests/    = 可自动运行的编辑引擎契约
examples/ = 可人工观察的宿主接入体验
benches/  = 可重复比较的性能事实
```

## `tests/`

`tests/` 是首选测试位置。它应该从外部使用者视角验证 crate root 暴露的 public API 是否稳定、正确、可依赖。

适合覆盖：

- Buffer 创建、读取、编辑和版本推进。
- Transaction、EditList、Delta、ChangeSet、PositionMap。
- Undo / Redo、SelectionSet 恢复和事务合并。
- 坐标转换、Unicode、CRLF、tab / display column、UTF-16 边界。
- Snapshot 只读语义、版本绑定和过期结果处理。
- Anchor、TrackedRange、MetadataLayer、VersionedRangeSet 等区间跟随。
- Fold / Projection / Viewport slicing。
- 搜索、替换、replace all 原子性。
- 大文件策略、只读策略、历史预算和错误输入。
- property / differential regression。

不适合覆盖：

- 私有函数和临时 helper。
- 只为了测试而暴露的内部结构。
- UI 渲染、窗口、鼠标事件细节。
- 性能数据和 benchmark。

## `examples/`

`examples/` 是可选的宿主接入实验台，不是纯 engine milestone 的验收底线。

它适合验证：

- 宿主输入能否正确调用 Buffer / Transaction / Selection API。
- UI 状态是否能与引擎状态同步。
- Snapshot、Viewport、Projection、Selection 等公共能力接入是否顺手。
- 人类操作下是否能观察到明显的状态错位或 API 摩擦。

它不应该重复证明编辑算法正确。Undo、坐标、搜索、多光标等核心行为应由 `tests/` 锁住。

## `src/tests/`

`src/tests/` 是例外路径。只有同时满足以下条件，才适合放入：

- 行为属于长期内部不变量。
- 破坏后会导致引擎语义错误。
- public API 难以精准覆盖。
- 为测试暴露 public API 不合理。
- 测试能提高重构安全性，而不是固定临时实现。

能通过 public API 覆盖的测试，优先放在 `tests/`。

## `benches/`

`benches/` 用于回答性能问题，不用于替代正确性测试。

适合覆盖：

- 局部插入、删除、替换和批量事务。
- 大文件、超长行和多光标编辑。
- 坐标转换、Snapshot clone、Viewport slicing。
- Fold / Projection 查询和切片。
- 搜索、正则搜索、replace all。

性能数据应服务趋势判断和回归排查，不承诺与真实宿主 UI 性能完全等价。

## 测试设计要求

- 测试名称表达编辑语义，而不是当前实现步骤。
- 失败信息应能定位职责边界或不变量。
- 错误输入要验证错误类型和原子性。
- 多版本能力要验证版本绑定、过期拒绝或 remap 行为。
- Unicode / CRLF / 超长行 / 多光标等边界应以最小样例表达。
- 不为了通过测试放宽生产校验。

## 常规验证

修改文档通常不需要跑完整测试；修改 Rust 代码通常至少运行：

```bash
cargo fmt
cargo test
```

触及性能或 benchmark 时，再运行：

```bash
cargo bench --no-run
```

没有实际运行的命令，回复中必须明确说明。
