# 跨平台能力边界

本文是 Zcv 跨平台架构的维护登记表。它记录每个能力域的统一入口、平台后端、权威状态、资源生命周期和验证边界。新增平台行为或系统调用前，应先更新这里，再修改实现。

## 能力域登记

| 能力域 | 统一入口与平台无关核心 | 平台后端 | 权威状态与资源所有者 | 原生验证 |
| --- | --- | --- | --- | --- |
| 窗口与几何 | `zcv-workspace` 的窗口布局持久化与恢复策略；GPUI 提供窗口和显示器语义 | GPUI；工作区持久化文件写入位于 `zcv-workspace/src/persistence/platform.rs` | `Workspace` 拥有布局持久化任务；GPUI 拥有原生窗口、显示器和缩放资源 | macOS/Windows 实机验证显示器切换、DPI、最大化与恢复 |
| 文本与输入 | `zcv-editor`、`zcv-terminal`、`zcv-ui` 消费统一布局、action 和输入语义 | GPUI `WindowTextSystem`、窗口输入与键盘映射；快捷键平台选择位于 `zcv-keymap/src/loader/platform.rs` | 编辑器、终端和 UI 各自拥有领域状态；GPUI 拥有字体、IME、窗口输入资源 | macOS/Windows 验证 IME、快捷键、命中测试和缩放 |
| 文件系统 | `zcv-fs-watch` 的 `Watcher`、`PathEvent`、注册和事件合并核心 | `zcv-fs-watch/src/fs_watcher/platform.rs`；负责路径语义、监听模式和原生 API | `GlobalWatcher` 拥有后端与注册生命周期；项目层只消费规范化事件 | macOS/Windows 验证递归、重命名、大小写和监听丢失 |
| 路径语义 | `zcv-path` 的 `AbsolutePathBuf`、`RelativePathBuf`、`normalize_for_comparison`、`stable_identity` 值语义 | `zcv-path/src/platform.rs`；只承载本机路径字符串语法与 Windows 扩展前缀转换 | 值类型不持有长期资源；配置目录与工作区身份分别由 `zcv-settings`、`zcv-workspace` 派生 | 平台无关测试覆盖相对路径规范化与稳定身份；Windows 原生验证扩展前缀与分隔符 |
| Git 子进程 | `zcv-git` 统一负责命令启动、取消、等待和结果语义 | `zcv-git/src/repository/platform.rs`；负责进程组或进程树控制 | `GitCancellation` 拥有一次操作的取消状态；后端拥有进程树控制资源 | Unix/Windows 验证取消、自然退出和残留进程 |
| 终端进程 | `Terminal` 拥有网格、事件流、尺寸和关闭状态 | `zcv-terminal/src/pty_info/platform.rs` 与 `alacritty.rs`；负责 PTY/ConPTY 和进程树 | `Terminal` 拥有会话状态；PTY 后端拥有 IO 与子进程资源 | macOS/Windows 验证 shell、resize、关闭和强制终止 |
| 自动更新 | `zcv-update` 的平台无关核心拥有清单、校验、事务编排、启动确认与回滚；helper 入口为 `run_helper` | `zcv-update/src/platform/` 后端负责 bundle/目录布局、原子切换/回滚原语与进程退出等待；`zcv-update-helper` 是同一后端的独立进程入口 | 更新事务拥有安装切换生命周期；`UpdateManager` 拥有应用级策略和用户反馈 | macOS 验证 bundle；Windows 验证占用、替换失败和回滚 |

## 不变量

- 业务模块只调用能力语义，不直接判断平台路径、系统命令或原生句柄。
- `cfg`、系统 API、平台路径和平台资源只出现在对应能力域的后端或明确的原生测试边界。
- 平台无关核心拥有状态机和错误语义；平台后端拥有自己创建的系统资源，并负责释放。
- 同一业务事实只有一个可写所有者；布局、终端状态、文件事件和更新事务不能在 UI 中保存第二份副本。
- 平台差异不能通过隐式 fallback、双写或兼容路径隐藏。无法保证同步时必须产生明确的错误或 `Rescan` 等语义结果。
- macOS 通过、Windows 未验证只能记录为部分验证，不能作为跨平台完成的结论。

## 验证分层

平台无关测试证明共同语义和状态转移：

- `cargo test -p zcv-fs-watch --all-targets`
- `cargo test -p zcv-update --all-targets`
- `cargo test -p zcv-terminal --all-targets`
- 受影响的 `zcv-git`、`zcv-workspace` 和应用策略测试

平台后端测试证明系统边界：

- macOS：文件监听、窗口恢复、PTY、bundle 更新和启动确认；
- Windows：文件监听、窗口恢复、ConPTY、进程树、文件占用、helper 替换和回滚；
- Linux/Unix：文件监听轮询、进程组和本地路径语义。

平台测试失败时，先判断失败属于平台无关核心还是后端适配，再修改对应边界。一个平台的通过结果不能替代另一个平台的运行时验证。

## Review 门禁

提交涉及平台行为时，审查者应确认：

1. 新增 `cfg` 是否位于真实平台后端或原生测试边界；
2. 业务层是否新增平台路径、系统命令、原生句柄或重复的路径/窗口/进程状态；
3. 平台后端是否同时拥有资源创建、使用、错误转换和销毁；
4. 是否补充了平台无关契约测试，以及目标平台的原生验证记录；
5. 新平台是否只需要替换后端，而不需要复制上层状态机；
6. 错误是否通过正确的用户交互边界呈现，而不是只输出到标准错误。

`scripts/check-platform-boundaries` 会检查变更中新增的平台实现是否离开登记的后端边界。它是辅助门禁，不能替代对状态所有权、生命周期和原生行为的人工审查。
